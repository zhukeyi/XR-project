# 决策日志（ADR-lite）

用途：记录**会影响接口或跨模块**的决定。你说"改这个"或"回滚这个"，先在这里留一条，再动代码。

规则：
- 每条有唯一编号，**只增不改**。改变主意就新开一条并注明"取代 ADR-XXX"。
- 状态：`提议` → `已定` → `已废`（被取代时）。
- 动契约的决定必须在"影响面"里列出受影响的字段与文件。

## ADR-001 机体尺度取 7.930 m

状态：**已定（2026-11-11 由 Codex 评审 `d5d763d` §1.1 书面确认）**
日期：2026-11-10（提议）／2026-11-11（拍板）

- **背景**：M1 于 11-08 由四条硬约束（载荷 ≥1.96 t、散热 ≤50%、接地 ≤200 kPa、质量闭合）解出 H = 8.0 m，实测 7.930 m；M2 的契约 v1.1（11-06）仍为 18.20 m。
- **选项**
  - A：以 7.930 m 为准，契约升 v1.2。（物理自洽，已出资产）
  - B：保留 18.20 m，回退 M1 造型。（视觉比例熟悉，但接地 327 kPa 超限、翼展 50.5 m 不可折叠）
  - C：折中 12 m。（两边都不满足，不推荐）
- **建议**：A。
- **影响面**：`MechaContract.cs` 39 float + 7 Vector3；4 个引用脚本；白盒重建；33 条自检中的尺寸项；M1 全部渲染产物作废重出。
- **回滚方式**：若拍板后反悔，`git revert` 该次 `[contract]` 提交即可回到 v1.1，但 M1 资产需重新按 18.2 m 出，成本约 2 天。

## ADR-002 座舱内构保持人类尺度，只重算离地高度

状态：**提议（与 ADR-001 绑定）**
日期：2026-11-10

- **背景**：机体从 18.20 m 降到 7.930 m，若等比缩放（×0.4396），座舱内空会从 1.60×2.00×2.20 缩到 0.70×0.88×0.97，人无法进入。
- **决定**：内空**不做等比缩放**，保持约 1.6×2.0×2.2 m；只把 `SeatAnchor` 离地高度从 11.55 m 重算到约 5.0 m，`chestSocketY` 从 12.60 同步下移。
- **影响面**：`chestSocketY`、`cockpitRootLocalY`、座椅/眼位/舱门开口、座舱 UI 布置、VR 内交互件距离。
- **风险**：若只改总高不改座舱，会出现"8 m 机体、18 m 座舱"的穿帮。

## ADR-003 `ref_assets/` 永久排除出公开仓库

状态：**已定**
日期：2026-11-10

- **背景**：`mecha_render/ref_assets/source/UNICORN_GUNDAM_OBJ.obj` 为第三方高达模型，属他人在先权利表达。
- **决定**：写入 `.gitignore` 永久排除，仅本地保留作内部度量参照；对外口径维持"语法借用、身份原创"。
- **理由**：赛制要求原创；公开仓库含该模型会构成明确风险，且与项目声明的合规口径自相矛盾。
- **影响面**：无代码影响；`.gitignore`。

## ADR-006 资产导出冻结：等造型定稿后再出 `mecha_793.glb`

状态：**已定（业主指令）**
日期：2026-11-10

- **背景**：M1 的造型正在做设计修改。此时若先导出 glTF，产出的几何必被后续修改作废；且 `02_资产交付规格` 里的六条尺寸断言会以过期几何为基准被"验过一遍"，反而制造虚假绿灯。
- **决定**：**暂停一切 glTF / FBX / VAT 导出**，直至造型定稿。定稿后一次性出 `mecha_793.glb` + `mecha_793.json` + atlas + VAT。
- **不进冻结范围**（照常推进）：分镜表 `shotlist.json`、渲染脚手架与断点续渲、VAT 烘焙工具、Unity `AssetPostprocessor` 断言脚本、`contract.json` 导出、契约 v1.2 常量改写。理由：这些只依赖**接口与流程**，不依赖最终几何。
- **前置放行条件**（三条同时满足才解冻）：
  1. 外形修改停止，`mecha_render/` 下造型脚本无未提交改动；
  2. 总高实测稳定在 7.930 m ± 0.02（造型改动若改变总高，须同步 ADR-005 换文件名）；
  3. 18 个具名枢轴名称与位置确认不再变动（枢轴改名等于改契约，走 §01 的六步变更流程）。
- **影响面**：M1 `tools/export_gltf.py` 的调用时机；M2 的导入目标文件缺失（先用白盒占位，不得改导入路径）；`00_项目状态` §5 第 4 项由「P0 待办」改为「P0 阻塞（外部）」；`§6` 两周路线 M1 段需重排。
- **回滚方式**：本条为冻结令，无需回滚；解冻即在决策日志追加 ADR-007 记录解冻时间与当时的几何指纹（总高、三角面数、材质数）。

## ADR-007 机体定位升级 v2，新增蜂群 / 集装箱 / 连接性三个系统

状态：**提议（待拍板，因为扩大 M2 范围）**
日期：2026-11-10

- **背景**：业主提出"实用性 + 连接性 + 体系化作战 + 可投送集装箱 + 高阶空降兵"构想。分析后确认这不只是叙事调整，而是**机体定位的主函数变更**：从"移动核电站"变为"可投送的蜂群母节点"。详见 `机体定位_v2_可投送能力集单元.md`。
- **不改动**：全部物理参数（34.9 t / 49.4 MWt / 22.3 MW / 27.9 MW / 1.96 t 载荷 / 128 kPa）。v2 只做加法与升级，不改数字。
- **新增三个系统（这是范围扩大，必须记）**：

| 系统 | 内容 | 宣传片档成本 | 可玩档成本 |
|---|---|---|---|
| `Container` 集装箱 | 壳板铰链、爆破螺栓、二次展开货舱 | 0.5 人日（程序化几何） | 2 人日 |
| `DroneSwarm` 蜂群 | 22 架 L0 + 280 架 L1、VAT、实例化、自组织织网 | 1.5 人日（VAT + 实例化） | 6 人日 |
| `CityNet` 连接性 | 五层接入、假目标注入、接入即暴露 | 0（只在 HUD 与字幕出现） | 3 人日 |

- **对 11/24 首版提交的判断**：**+2 人日，可承受**。三个系统在宣传片里只需"看起来像"——集装箱是几何、蜂群是 VAT、连接性只进 HUD。**终点不变。**
- **对 v1.0 可玩版的判断**：**+11 人日**。这是真实的欠账，应在 11/24 后单独排。
- **影响面**：M2 模块划分（新增 3 个子系统）；33 条合规自检需增补约 8 条（集装箱接口尺寸、蜂群实例数上限、连接层开关）；`MechaContract.cs` 需增 `containerSocket` 等少量字段；`00_项目状态` §6 排期需重排。
- **回滚方式**：v2 是纯加法，`git revert` 对应 `[docs]` 提交即回到 v1 定位，物理参数与 M1 资产完全不受影响。**这是本决策可以放心拍板的原因——它没有沉没成本。**

## ADR-008 母舰级平台「驼峰」：取消回收、826 t、片中不出场

状态：**提议（待拍板）**
日期：2026-11-10

- **背景**：业主参照白色木马 / 大天使号 / 南天门「鸾鸟」提出母舰级平台设计需求。分析见 `母舰平台_驼峰级.md`。
- **四条关键决定**
  1. **取消回收能力**（无甲板、只有弹舱）。一有甲板即滑回"保护母舰"的日式叙事，与 v2 的"投送"路线冲突。
  2. **吨位 826 t / 翼展 130 m**，而非 12 万吨级。不装飞机只装 8 个箱子——飞机需要机场，箱子只需要吊车。
  3. **12–15 km 巡航，不待机只过顶**（11 min 窗口 / 9 h 周期 / 250 km 外投放）。20 km 待机需 5,303 m² 翼面积，物理上不成立。
  4. **不引入虚构物理**（无力场/反重力）。12 万吨级必需力场，那会拆掉本项目唯一的结构性优势。
- **范围影响**：**0 人日**。建议 60 秒宣传片中母舰不出场（仅雷达光点 + 无线电），2 分钟导演版再一次掠影（+4 人日）。
- **影响面**：新增文档 `母舰平台_驼峰级.md`；`shotlist.json` 若采用"不出场"方案则无需新增背景预设；`00_项目状态` 无需改动。
- **回滚方式**：纯文档，删除该文档即回到无母舰状态。**无代码、无资产依赖。**

## ADR-009 赛程修正：截止 12/19，11/24 不是终点；资产拆两条路径

状态：**已定（赛程为客观事实，非选择）**
日期：2026-11-11

- **背景**：Codex 评审 `d5d763d` §9 指出截止日为 12/19，与我方 `00_项目状态` §6 的"11/24 终点"冲突。经三个独立来源核实（映维网 / VRAR星球 / 新浪），确认：11/25 开放提交、**12/19 09:00 报名与提交同时关闭**、12/19–23 初筛、12/24 公布入围、12/26 北京大钟寺 F3 决赛路演。
- **决定一（排期）**：11/24 降级为"首个可玩版本门"，硬截止为 12/19。多出 25 天，全部投入垂直切片与设备验收，**不投入新增玩法**。
- **决定二（冻结风险解除）**：ADR-006 的最大风险"造型定稿晚导致渲染窗口不足"被证伪。造型定稿可放宽到 **11/20**，宣传片渲染窗口 11/20–12/10（20 天），成片 12/12。**不压缩镜头数、不降采样。**
- **决定三（资产路径分离）**：`export_gltf.py` 定位从"交付资产"降级为"**宣传片资产 + 灰模**"；引擎内资产另开 Blender Armature → skin 链路。

| 路径 | 动画方式 | skin | 工具 |
|---|---|---|---|
| 宣传片（预渲染） | 节点 TRS 关键帧 | 不需要 | `export_gltf.py` 可用 |
| 引擎内（Unity） | Armature + Skin | 必须 | Blender 导出链路 |

- **理由**：宣传片在 Blender 内逐帧改枢轴角度即可，渲染器不关心 skin；只有运行时骨骼动画才需要 SkinnedMeshRenderer。混为一条会导致"重写 M1 导出器"的误判。
- **影响面**：`00_项目状态` §6 整表替换（见 `05_评审回应与排期修正.md` §6）；`02_资产交付规格` 需拆两条口径；M1 无需重写导出器。
- **回滚方式**：若赛程再变，追加新 ADR 覆盖本条；排期为外部事实，不适用 revert。

## ADR-010 《落区》台本为唯一体验基线；预告片顺序待拍板
状态：**部分已定 / 一项待业主拍板**
日期：2026-11-11

- **背景**：`7a39ce4`（Kimi）提交 `docs/钢脊_PICO_XR沉浸体验台本_落区.md`（588 行）与 `docs/production/dropzone_p0/` 六份可执行契约；`d5d763d`（Codex）在此基础上出评审。业主确认两者是**联合输入**，不是前后两版。
- **决定一（台本唯一化，已定）**：以《落区》S00–S07 **八拍**为唯一体验基线，替代旧九拍（登机/启动/CIC/弹射/驾驶/射击/近战/返航/结算）。旧九拍中的"登机"与"返航"在本作**物理上不存在**（人是被投下来的；母舰不回收，见 ADR-008）。
- **决定二（CIC 定性，已定）**：CIC = **机载任务系统的预置语音**，不依赖后方实时通信。此条修掉《投送》原稿的最大连续性漏洞——灰雨通信拒止环境下母舰九小时后才过顶，不可能实时对话。
- **决定三（冷却项，已定）**：实时城市物联网降 P1；P0 用「投送前缓存的战术情报包」完成"复核"认知教学，与 v2 §5「T+40 min 才全域并网」时间轴一致。敌方多机下坠降 P1（改失联离场）。
- **决定四（预告片顺序，⚠️ 待拍板）**：《落区》§9 与 04 §9 均把「高采样第三人称离线预告」列为 P1、不阻塞可玩版；而业主要求"**最开始先完成预渲染的宣传片**"。两者顺序相反。

| 方案 | 做法 | 建议 |
|---|---|---|
| **A 双轨并行** | 造型 11/20 定稿 → 解冻即开渲 11/20–12/10；Unity 侧同步做灰盒八拍 | **推荐**。ADR-009 已把渲染窗口放宽到 20 天，"先出片"与"可玩版不落后"在 12/19 下不互斥；真正约束是造型定稿日 |
| B 先灰模预演片 | EEVEE 灰模 60 s，1–2 天 | 给评审看结构，不能当正式物料 |
| C 服从台本 | 高采样预告彻底 P1 | 仅在可玩版严重滞后时启用 |

- **决定五（头蹭箱盖，建议分路径）**：XR 第一人称下降 P1（玩家眼位在头内，看不见自己头顶蹭盖）；film 第三人称**保留**——它是 8 m 尺度最强的锚点。替代方案（前臂掠过 + 阴影 + 地面参照）对 XR 成立、对片子偏弱。
- **影响面**：`05_评审回应与排期修正.md` §8 全文；`02_资产交付规格` §3/§5/§6 的骨集口径须改为引用 `rig_contract.json`（18 = 16 机体骨 + 2 挂架骨，SeatAnchor/ChestSocket 排除在 skin 外）。
- **回滚方式**：台本唯一化不可回滚（业主已确认联合输入）；决定四在造型定稿日前均可改选 B 或 C。
