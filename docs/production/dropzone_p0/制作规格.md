# 《钢脊：落区》P0 Blender 分场景组件与刚体绑定制作规格

版本：1.0.0（2026-11-11）
性质：**供建模、绑定、动画和 Unity Agent 执行的 proposed contract**
边界：当前仍是规格，不是已生成资产；不修改正式 `MechaContract`，不解除 ADR-006，不导出 glTF／FBX／VAT。

## 1. 唯一入口与读取顺序

其他 AI 不得只读叙事台本后直接建模。按以下顺序读取，并以机器可读文件为执行依据：

1. [scene_components.json](scene_components.json)：坐标、材质、组件、包围盒、碰撞、LOD、场景实例、路线与输出路径；
2. [rig_contract.json](rig_contract.json)：18 个机体骨、父子关系、head/tail、限位、Socket、网格绑骨映射及辅助刚性节点；
3. [animation_tracks.json](animation_tracks.json)：关键帧、程序蜂群、接触约束、输入驱动件和动画事件；
4. [mission_graph.json](mission_graph.json)：任务状态、守卫、输入、热沉、误判、过热、提示、检查点和验收用例；
5. [validate_contracts.py](validate_contracts.py)：结构、引用、数值和命名静态检查。

叙事依据是 [《钢脊：落区》PICO XR 沉浸体验台本](../../钢脊_PICO_XR沉浸体验台本_落区.md)。若叙事与 JSON 数值冲突，先提出契约修订，不得由单个 Agent 静默选择一套。

## 2. 坐标、单位和左右侧

统一使用米制，契约空间为右手系、Y-up、正面 +Z、左侧 +X。机体站立时脚底最低点为 y=0，任何资产导入后不得再次缩放。

Blender 原生 Z-up 与契约空间的转换固定为：

```text
[x_b, y_b, z_b] = [-x, z, y]
[x,  y,  z]     = [-x_b, z_b, y_b]
```

该变换是旋转，不是缩放，行列式为 +1。位置、骨骼 head/tail、网格顶点、法线、旋转矩阵必须走同一基变换；禁止只转换位置而保留原旋转。JSON 中的 Euler 均为**契约空间的父局部 XYZ 角度（度）**，不可直接当作 Blender 骨局部 Euler 写入。

场景地面 y=0。集装箱实例中心为 `(-7, 0, -4)`，旧变电站平台中心为 `(0, 0, 22)`，母线接口为 `(0, 0, 20.5)`。完整路径节点和净宽见 `scene_components.json#route`。

| `cockpit_human_scale` | 座椅、面板、操纵杆、按钮、授权柄、母线柄 | 独立刚性节点，不计入 18 骨 | 5–8 万 | 6 |

所有 `output_glb` 和 `output_report` 都是解冻后的规划路径。当前不得因为规格已写完就宣称资产已交付。

### 人体尺度座舱

座舱资产原点在地板中心，内空 1.45 × 1.70 × 1.60 m，坐面高 0.43 m，`SeatAnchor` 为局部 `(0, 1.15, -0.10)`。主面板距眼约 0.68–0.88 m。座舱通过 `ChestSocket → cockpit_level → cockpit_root` 挂载，缩放恒为 `(1,1,1)`。

`cockpit_level` 是机械调平节点，不是第 19 根机体骨，也不是相机控制节点。撑起时它抵消机体 root 的 X 角，保持座舱 upright；玩家头显姿态始终由 OpenXR 追踪提供。

### 运输内腔是硬约束

旧设定保留 6 × 2.5 m 箱底。本规格采用 2.30 × 3.10 × 5.80 m 的运输内腔目标，并要求 `stowed_transport` 实测包络不超过 2.20 × 2.90 × 5.60 m。肩甲通过既有 `shoulder_L/R` 折叠，不新增骨骼。

这只是**待验证的机构方案**。若肩甲、座舱调平外框或腿部在运输／撑起时穿插，必须改机构或走 ADR 变更；禁止整体缩机体、隐藏穿插部件或放大 Unity 容器来制造假通过。

## 4. 18 骨与辅助节点

机体骨的准确数量与名称为：

```text
hips chest head backpack
shoulder_L shoulder_R elbow_L elbow_R
hip_L hip_R knee_L knee_R ankle_L ankle_R
hatch_hinge_L hatch_hinge_R rack_L rack_R
```

其中前 16 个是机体骨，`rack_L/R` 是 L0 挂架骨。没有 `wrist`、IK、twist 骨；右掌、炮口与 L0 出口用 Socket 表达。

主要映射：上臂和肩甲→`shoulder_*`，前臂、手与右炮→`elbow_*`，大腿→`hip_*`，小腿→`knee_*`，脚→`ankle_*`，舱门→`hatch_hinge_*`，L0 挂架→`rack_*`。完整逐组件映射只在 `rig_contract.json#mesh_bindings` 中维护。

辅助节点分为两类：座舱的调平、操纵杆、按钮和控制柄；集装箱的壳板与 L1 舱盖。它们都是整件 TRS，不参与机体 Armature 权重。

## 5. Blender 建模与刚体绑定算法

### 5.1 建模

1. 清空默认 `Cube`、`Camera`、`Light`，创建资产集合与 `mecha_root`。
2. 按 `scene_components.json` 的 `rest_world_mecha` 包围盒制作分件。胸舱必须是空腹桁架与外壳，不得用实心盒填满座舱空间。
3. 倒角、桁架、面板缝和材质在分件阶段完成；第三方高达参考网格与贴图不得进入交付。
4. 所有组件保持唯一 `component_id`，材质只引用本资产 `materials_used` 白名单。
5. 先将契约坐标转换为 Blender 坐标，再建立骨骼和网格；不要在导出前临时补一次不明轴向旋转。

### 5.2 建骨

```python
for spec in rig["bones"]:
    edit_bone = armature.edit_bones.new(spec["name"])
    edit_bone.head = C @ Vector(spec["head_world_m"])
    edit_bone.tail = C @ Vector(spec["tail_world_m"])
    edit_bone.roll = 0.0
for spec in rig["bones"]:
    if spec["parent"] != "mecha_root":
        bones[spec["name"]].parent = bones[spec["parent"]]
```

骨局部 Y 沿 head→tail。实际导出前必须重新读取世界与父局部矩阵，核对父级、位置和 roll；不能仅检查名字存在。

### 5.3 绑定

```python
for component in mecha_components:
    bone_name = component["bind_bone"]
    group = component_obj.vertex_groups.new(name=bone_name)
    group.add(list(range(len(component_obj.data.vertices))), 1.0, 'REPLACE')
    modifier = component_obj.modifiers.new("RigidSkin", 'ARMATURE')
    modifier.object = armature_object
```

随后合并机体分件为一个带多材质 submesh 的蒙皮网格，保留同一 Armature。每个启用的 LOD 在 Unity 中只能有一个 `SkinnedMeshRenderer`；LODGroup 的切换不等于同时显示多个 renderer。

逐顶点断言：恰好一个非零 influence，值为 1.0，权重和误差 ≤ `1e-5`，未加权顶点为 0，形态键为 0。液压管、线束、安全带和柔性护套在 P0 也采用分段刚性网格，不启用软变形白名单。

### 5.4 辅助机械件

按 `rig_contract.json` 的节点原点建 Empty，把对应整件网格放到节点下。顶点保存在节点局部空间，旋转只改变节点 TRS。不得把舱门或按钮的所有顶点写进世界坐标，否则开门时会绕场景原点飞走。

## 6. 动画与 XR 状态的关系

Blender Action／NLA 名称使用 `clip_id`。所有轨道采用单调非减时间键，末键不得晚于 clip 时长；通用步行使用 in-place，路线平移和转向由 Unity 控制器提供。

`mecha.stow_to_stand` 是本场景专用 root 曲线；`mecha.crouch_bus` 允许刚性两骨 IK 微调肩／肘，使 `palm_bus_R` 接触接口，但不得拉伸手臂或改变顶点权重。支撑脚滑移、穿地和掌心接触必须实测，不是看完视频就算通过。

输入驱动件标记为 `input_synchronized=true` 时，必须从当前机械角度续接，不得在确认输入后跳回第 0 帧。撑起、L1 和蹲下使用锁存命令，动画完成时不依赖已经结束的输入脉冲。

动画事件与玩法事件分离：

- `cannon_airburst` 只在授权闭合且未消费时有效；
- 播完 `mecha.aim_fire` 不自动获得下一次授权；
- 播完 `station.power_on` 前，`position_online` 不得提前为真；
- 玩家在 S06 保留干扰时，母线输入必须进入 `S06_OVERHEAT`，不能因动画已开始而跳过；
- XR 正片任何轨道都不得控制相机或 XR Origin。

## 8. 检查点与恢复

检查点直接采样 `clip_states` 设置姿态，并恢复任务变量、路线节点、热沉、授权日志、误判与过热计数。未列出的 clip 恢复为第 0 帧。不得用 20 倍速重播此前动画冒充恢复。

暂停必须冻结任务、动画、蜂群、提示、触觉和过热计时。控制器或追踪丢失时不得自动替玩家授权、开火或合闸。P0 无随机死亡，软土只平缓止停，过热可恢复。

## 9. 两级验收

### A. 当前可执行的静态验收

运行：

```bash
python3 docs/production/dropzone_p0/validate_contracts.py
```

检查 JSON 语法、唯一 ID、18 骨与父子关系、组件绑骨覆盖、动画目标、时间键、关节限位、任务状态与 clip 引用、检查点时间、主时间轴、场景实例与路线引用。

### B. 解冻后必须执行的几何与真机验收

静态 JSON 合法**不代表模型可交付**。仍需：

1. Blender 实测站立与运输包围盒、穿插、座舱调平净空、骨矩阵和逐顶点权重；
2. 实测动画关节限位、支撑脚滑移、穿地与掌心接触；
3. 实测三角面、材质、submesh、游离物体与 LOD；
4. Unity 执行 `M01–M11`，覆盖授权硬锁、过热、暂停、命令锁存、检查点和离线；
5. PICO 真机验证帧时间、热状态、字幕、手部可达性和舒适性，不能用 Mac 或模拟器替代。

## 10. 推荐实施顺序

先以灰盒实现组件原点、18 骨、辅助节点和任务状态图，再验证运输／撑起／蹲下三个高风险姿态。几何门槛通过后才投入桁架细节、贴图、蜂群表现与高质量预告。正式敌机另建资产，P0 的 `TARGET_REAL` 只是同尺度 L0 占位，不得以缩放伪装新型号。

高采样第三人称预告、头蹭箱盖、跨墙、多机下坠、VAT、地面无人车和实时 L2 城市网均不阻塞 P0。P0 的首要交付是**离线可玩、状态可恢复、绑定可验收**。
