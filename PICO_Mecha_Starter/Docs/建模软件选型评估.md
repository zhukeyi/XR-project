# 建模软件选型评估

项目：《钢脊：立于大地》PICO OpenXR 参赛版  
日期：2026-11-08  
基线来源：`Docs/Unicorn包导入实测与差距评估.md`（**真导入 + 真渲染**，非推测）  
本机：MacBook Air（Apple M4，10 核，16 GB 统一内存，无风扇），macOS 15.7.9，可用磁盘 181 GB，**当前未安装任何建模软件**

---

## 1 结论先行

### 1.1 三句话

1. **工具不是瓶颈，工时是。** 把 Unicorn 包实测出的 375 分件 / 377,328 三角 / 25 材质 / 81 张贴图折算成工序，熟练硬表面美术需 **262–408 小时**（7–11 周），而比赛窗口只剩 **4 周（约 144 小时）**。任何软件都改变不了这个缺口，只能靠**做减法**或**外包**填。
2. **推荐 Blender 5.2 LTS 为基座，不是因为它是"最好的建模软件"，而是因为它是唯一能同时容纳"程序化生成"和"手工精修"的免费平台。** 你的比较优势是写代码而不是雕模型，所以选型要最大化程序化的杠杆——`mecha_render` 已有的路线 C（曲面基底 + 倾斜板壳）应当用 Geometry Nodes 移植进 Blender，而不是推倒重来。
3. **Plasticity 与 Substance Painter 都是"局部放大器"，不是必备门槛。** Plasticity（$175）只在精修 P0 三件（头 / 胸舱 / 座舱）时值这个钱，先用它的 30 天免费试用判断值不值；Substance Painter（Steam 买断 $199.99）则直接解决 Unicorn 包暴露的那个坑——它自带 Unity URP 导出预设，一次导出 `_BaseMap / _BumpMap / _MetallicGlossMap / _OcclusionMap`，不会再出现"81 张图只有 27 张生效"。

### 1.2 决策表

| 问题 | 结论 | 依据 |
|---|---|---|
| 主力建模软件 | **Blender 5.2.3 LTS**（免费，2026-10-22 发布，2 年 LTS 支持） | 唯一开源 + 原生 Apple Silicon + 可脚本化 + 有 Geometry Nodes |
| 硬表面加速 | **HardOps + BoxCutter 捆绑 $38** + **MACHIN3tools $8** + **MESHmachine $44.99** | 布尔切割 → 倒角修复的完整链，机甲件的标准工作流 |
| 要不要 CAD | **先试用，暂不买**。Plasticity Indie $175，Starter 版免费 30 天（非商用） | 它的价值在 Parasolid 水密布尔与倒角；痛点明显时再掏钱 |
| 贴图 | **Substance 3D Painter 12（Steam 买断 $199.99）** | 直接出 URP 布局；学生免费版仅限非商用，比赛不宜用 |
| UV | Blender 自带 + **Zen UV $39**（够用）或 UVPackmaster 4 PRO $55 | 4 张图集规模不需要工业级打包器 |
| 绑定 | **Blender 空物体层级 + 契约 `Pivot_*` 命名**，不用骨骼 | 契约只要 7 个枢轴，骨骼是过度设计 |
| AI 生成几何 | **只用于 blockout 探索，不进最终交付** | 生成式必改细节 + 本机 16 GB 跑不了 TRELLIS.2（已实测） |
| 引擎 | **Unity 2022.3.62f3 + URP 14**（不变） | 已在 23 脚本 0 error 上验证，换版本等于退回待验证 |
| 不建议 | UE5（已废止）、Maya、ZBrush、Rhino、Cinema 4D、Fusion 360 | 见第 9 节 |

### 1.3 一句话采购结论

**先花 $90.99 买三个 Blender 插件（HardOps+BoxCutter $38 / MACHIN3tools $8 / MESHmachine $44.99），本周就能开工；Substance Painter 的 $199.99 等中模定稿、UV 展开完成之后再买**——因为它的 30 天试用从"你按下开始"计时，把 UV 没做完的时间烧在试用期里是最常见的浪费。

## 2 先把「Unicorn 程度」翻译成可验收的硬指标

"达到这样的程度"是感受，不能验收。用实测数据把它拆成六条：

### 2.1 六条硬指标

| # | 指标 | Unicorn 实测值 | 我们该定的目标 | 差距性质 |
|---|---|---:|---:|---|
| 1 | 分件数（可独立定位的件） | **375**（全平级，语义嵌在 60 字符名字里） | **≥ 180**，按 `Pivot_*` 契约命名 | 可降——契约只要求 7 个可动枢轴 |
| 2 | 三角面 | 377,328 | 350k–500k（预算 900k 的 39–56%） | **已达标**，不需增加 |
| 3 | 材质槽 | 25 | ≤ 30（我们自己的上限） | 持平 |
| 4 | 贴图 | **81 张**（9 部位 × 白/红/其他 × COL/BUMP/SPEC），实际生效 27 张 | **20 张**（4 图集 × 5 图） | 可降——图集化 |
| 5 | 座舱内构 | **36 件 / 14 项语义部件**（座垫 / 头枕 / 三显示器 / 油门 / 扶手 / 双脚踏 / 球形舱 / 前舱门 / 滑轨） | 18 件（外包清单 A3 已列全） | **不可降**，这是贴脸看的部分 |
| 6 | 可动性 | 带 `inner_frame` / `ball_joint` / `slide_G`，原资产有骨架（OBJ 导出时丢失） | 分件刚体 + 7 枢轴 + 舱门 0–95° | 可降——不用全身骨骼 |

### 2.2 哪些必须达到、哪些可以放过

这是全篇最关键的一张表。VR 的观看方式决定了**不是每一处都值得花同样的工**：

| 部位 | 观看距离 | 视觉权重 | 该达到的精度 |
|---|---|---:|---|
| **座舱内景** | 0.2–0.9 m（贴脸） | **≈ 45%** | **必须 Unicorn 级**：材质分层、按钮独立、缝隙真实 |
| **头部 / 胸舱** | 2–6 m（序章仰视） | ≈ 25% | Unicorn 级的 80%：轮廓与板缝要硬，铆钉可用法线假 |
| 右臂 / 光剑 | 1.5–4 m（持剑时近） | ≈ 15% | 中等：关节分件正确，握持不穿模 |
| 腰裙 / 左臂 | 3–8 m | ≈ 8% | 中等偏低：轮廓与材质一致即可 |
| 腿脚 / 背包 | 6–18 m（多数时间在视野下缘或背后） | ≈ 7% | **可以放过**：程序化几何 + 法线细节 |

**推论**：追求"整机 375 件 / 81 张贴图"是把工平分到看不到的地方。正确的分配是**座舱超配、腿脚欠配**，而 Unicorn 包恰好相反——它的 110 件腿脚占 31% 面数，因为它是要摆着看的静态模型，不是要坐进去的载具。

## 3 达到这些指标要多少工时（这是选型的前提）

不谈工时的选型是许愿。以下按"熟练硬表面美术"与"你本人"两条线估：

### 3.1 分工序工时（单位：小时）

| 工序 | 产出 | 熟练美术 | 你（有代码基础、零建模基础） |
|---|---|---:|---:|
| 原创三视图 | 正 / 侧 / 背 + 座舱剖视 | 16–24 | 30–40 |
| 中模 blockout | 180–375 件体量正确 | 40–60 | 80–120 |
| 硬表面精修 | 倒角 / 板缝 / 散热格栅 | 60–100 | 150–250 |
| 座舱内构 14 项 | 贴脸精度 | 40–60 | 60–90 |
| UV | 无重叠 + 边距达标 | 20–30 | 40–60 |
| 贴图（81 张口径） | PBR 五图 | 50–80 | 60–100 |
| 绑定 + Pivot 对齐 | 契约 7 枢轴 | 20–30 | 30–50 |
| 引擎整合 / LOD / 合批 | DC ≤ 200 | 16–24 | 20–30 |
| **合计** | | **262–408** | **470–740** |

折算：熟练美术 7–11 周（36 h/周）；你 13–21 周。**比赛窗口 4 周 = 约 144 小时。**

### 3.2 做减法之后仍然不够

按第 2.2 节的优先级降配（分件 375→180、贴图 81→20、腿脚用程序化），工时降到：

| 工序 | 降配后 | 说明 |
|---|---:|---|
| 三视图 | 16–24 | 不变，AI 出候选再修 |
| 中模 180 件 | 30–45 | 件数减半 |
| 精修（仅 P0 三件） | 30–45 | 其余部位靠程序化 + 法线 |
| 座舱 18 件 | 40–60 | 不降 |
| UV 4 图集 | 12–18 | 图集化后打包量降 4 倍 |
| 贴图 20 张 | 30–45 | |
| 绑定 + 枢轴 | 20–30 | |
| 整合 / LOD / 合批 | 16–24 | |
| **合计** | **194–291** | 仍需 5.4–8 周 |

**结论：降配到极限，仍超窗口 1.3–2 倍。** 这就是第 1 节"工具不是瓶颈"的算术依据。4 周里单人能真实交付的上限是：

> **程序化基底 + 4 张图集 + 座舱精修 + 头胸舱中等精度 ≈ 120–140 小时**，对应的质量定位是"风格化 PBR 机甲"，与 Unicorn 的差距是：分件数约 1/2、贴图数约 1/4、细节锐度差一档。

要达到 Unicorn 级，只有三条路：**外包 P0 三件**、**延长赛程**、**接受降配**（第 6 节展开）。

## 4 软件分层：六道工序各选谁

### 4.1 总览

```
① 几何基底 ──→ ② 硬表面精修 ──→ ③ UV ──→ ④ 贴图 ──→ ⑤ 枢轴/绑定 ──→ ⑥ 引擎
   GN 程序化       Blender+插件      Blender     Painter       Blender 空物体    Unity
   （或 Plasticity）                                   （或 Blender 烘焙）    FBX 2020
```

### 4.2 几何基底：两条入口，不冲突

| 入口 | 工具 | 擅长 | 成本 | 什么时候用 |
|---|---|---|---|---|
| **程序化** | Blender **Geometry Nodes** | 从线稿/轮廓批量生成板壳、按规则分布板缝、一处改参数全机跟随 | 免费，但要写节点 | **默认入口**——你已经有一条跑通的路线 C |
| **实体建模** | **Plasticity**（Indie $175） | Parasolid 内核的布尔与倒角，水密、可直接给 3D 打印或工程核对 | $175 买断 | 精修头 / 胸舱 / 座舱这类"以面与倒角为主"的件 |

**Plasticity 的三条硬限制（买前必须知道）**：

1. **不导出 FBX**——Indie/Studio 都只有 STEP / OBJ / STL / Parasolid 导出，FBX 仅支持导入。回 Blender 只能走 OBJ（丢材质层级）或 STEP（丢 UV，需重展）。
2. **无骨骼、无动画、无渲染器、无参数化历史**。它是"零件的软件"，不是"资产的软件"。
3. Indie 许可绑定 **1 人 / 2 台机器**，商用允许；`Starter` 免费版 30 天但**禁止商用**——比赛作品若后续商业化，用 Starter 做的东西不能带走。

因此正确用法是：**在 Plasticity 里把单个零件做到满意 → 导出 OBJ/STEP → 回 Blender 装配 + UV + 枢轴**。不要指望它承担整条管线。

### 4.3 硬表面精修：Blender 插件是效率分水岭

单价全部核实于 2026-11：

| 插件 | 价格 | 作用 | 必要性 |
|---|---|---:|---|
| **HardOps + BoxCutter** | **$38**（捆绑，Superhive；Gumroad 单买 $19 each） | BoxCutter 在视口里直接画切割布尔；HardOps 用一个 Q 菜单管倒角、镜像、锐边、修改器栈 | **必买**——机甲件的标准做法 |
| **MACHIN3tools** | **$8**（Prime）/ $20（DeusEx） | 饼菜单、智能选择、对齐、清理，纯效率 | **必买**，$8 是全清单里性价比最高的 |
| **MESHmachine** | **$44.99** | 布尔之后修倒角、重塑过渡面 | **建议买**——布尔切完倒角不干净是常态，没有它就得手工补面 |
| Fluent 4 | $20–57 | HardOps 的温和替代，曲线更平缓 | 不买，与 HardOps 功能重叠 |
| Random Flow / OCD / Hard Surface Detailer | $15 起 | 生成机械细节（greeble） | 可选，做腿脚/背包的"欠配区"时省事 |
| Grid Modeler / Construction Lines | $20 / $11 | CAD 式精确构造 | 可选，若你习惯从 CAD 思维建模 |

关于学习曲线要诚实：**HardOps 是键位驱动的模态工作流，不是按钮面板，第一周会很难受**（社区共识）。这笔成本比 $38 大得多，但它决定了"一天做 10 个件"还是"一天做 3 个件"。

### 4.4 UV：够用即可

| 工具 | 价格 | 判断 |
|---|---:|---|
| Blender 自带（Smart UV Project + 手动接缝） | 免费 | **4 张图集规模完全够用** |
| **Zen UV** | $39 | 建议——接缝/密度/打包一键化，省 30–40% UV 时间 |
| UVPackmaster 4 PRO | $55 | 不必——它的优势在几十个 UV 岛的工业级打包，我们只有 4 张图集 |
| TexTools | 免费 | 备用，检查 texel density 一致性 |

### 4.5 贴图：Substance 是唯一"一次做对"的选项

| 方案 | 价格 | 能到 Unicorn 的 81 张水准吗 |
|---|---:|---|
| **Substance 3D Painter 12（Steam 买断）** | **$199.99** | **能**。功能更新到 2027-03，之后永久持有该版本 |
| Substance 3D Texturing 订阅 | $24.99/月（年付 $249.88） | 能，但 12 个月成本高于买断 |
| Substance 3D Collection | $59.99/月 | 不必，Stager/Modeler 用不上 |
| 学生 / 教师免费 | $0（**仅个人非商用**） | 技术上能，但**比赛作品不建议**——一旦商业化，授权链不干净 |
| Blender 程序化材质 + Bake | 免费 | 到"风格化"上限；划痕、锈迹、编号喷字这类**靠贴图讲故事**的细节做不出来 |

**为什么它直接解决 Unicorn 的坑**：Unicorn 的 81 张贴图是 COL / BUMP / SPEC 三通道的老式 PBR，内置 OBJ 导入器只认 `map_Kd`，于是 54 张被静默丢弃。Painter 的 **Unity URP 导出预设**输出的是 URP/Lit 的槽位布局：

```
_BaseMap          ← BaseColor（sRGB）
_BumpMap          ← Normal（Linear）
_MetallicGlossMap ← R:Metallic  A:Smoothness（打包）
_OcclusionMap     ← AO（灰度）
```

一次导出即可被 URP 直接吃下，不需要在 Unity 里手动重挂 54 张贴图。**这是"买 Painter"而不是"用 Blender 手搓材质"的关键工程理由**，不是画质理由。

### 4.6 枢轴与绑定：不要用骨骼

契约表要求的是 7 个枢轴：

| 契约枢轴 | 父级 | 轴向 | 角度 |
|---|---|---|---:|
| `Pivot_StickBase` | 座舱地板 | X | ±25° |
| `Pivot_Throttle` | 座舱地板 | X | 0–40° |
| `Pivot_Hatch_L/R` | 同 `HatchHinge_L/R` | Y | 0–95° |
| `Pivot_Skirt_Front` | 胯部 | X | ±12° |
| `Pivot_Skirt_Side_L/R` | 胯部 | Z | ±10° |
| `Pivot_Elbow_R` | 右肘 | X | 0–120° |
| `Pivot_Wrist_R` | 右腕 | XYZ | 自由 |

**这全部是空物体（Empty）层级就能表达的刚性旋转**，不需要 Armature、不需要蒙皮权重、不需要 Quad Remesher。

- Unicorn 包有 0 个 SkinnedMeshRenderer，也照样能开舱门、拔光剑——因为它靠的是分件 + 枢轴，不是骨骼。
- 什么时候才需要骨骼：走路 / 挥剑 / 变形。这是 `Unicorn包导入实测与差距评估.md` §5 的 D 阶段，3–6 周，**本轮不做**。
- 万一将来要做：Blender Armature + Auto-Rig Pro（$50 Full / $25 Lite）比 Rigify 更适合机械体——Rigify 是给人形生物的。

### 4.7 引擎内：Unity 不变

| 项 | 值 |
|---|---|
| 引擎 | Unity **2022.3.62f3** |
| 管线 | **URP 14.0.12** |
| 导入格式 | **FBX 2020**（Y-up、1 unit = 1 m、Apply Transform、预先三角化） |
| 材质数上限 | 30（与 Unicorn 的 25 同量级） |
| Draw Call 目标 | ≤ 200（Unicorn 的 375 超 1.9×，必须合批） |

导出的三个坑（都在实测里踩过）：

1. **不要用 glTF 代替 FBX**——glTF 在 Unity 里会重建层级，`Pivot_*` 的空物体可能被压平，而契约是靠**按名字查找**的。
2. **FBX 导出勾 `Apply Scalings: FBX All` + `Apply Transform`**，否则进 Unity 后 0.01 缩放再来一次。
3. **导出前三角化**，n-gon 在 Unity 里会被隐式三角化，UV 接缝可能裂。

## 5 推荐组合：混合路线

### 5.1 管线

```
线稿 / 概念图
   │
   ├─[A] Blender Geometry Nodes ── 曲面基底 + 167 板壳（移植 mecha_render 路线 C）
   │         ↓ 参数化：改一处，全机跟随
   │
   ├─[B] Plasticity（可选，仅 P0 三件）── 头 / 胸舱 / 座舱的实体布尔与倒角
   │         ↓ 导出 OBJ / STEP
   │
   ├─[C] Blender + HardOps/BoxCutter/MESHmachine ── 布尔切割、倒角修复、装配
   │         ↓ 建 Empty 层级，命名对齐 Pivot_*
   │
   ├─[D] Blender + Zen UV ── 4 张图集，边距 ≥ 4 px（2K）
   │
   ├─[E] Substance Painter ── Unity URP 预设导出 BaseColor/Normal/Mask/AO
   │
   └─[F] Unity 2022.3.62f3 + URP 14 ── ArtRoot 下替换，代码零改动
             ↓
        Tools/compile-check.sh（23 脚本 0 error 门禁）
```

### 5.2 为什么不是"纯 Blender 从零捏"

纯手工路线在纸面上上限最高（可以做到 Unicorn 的 375 件 / 81 图），但它把全部 262–408 小时压在一个人身上，且**没有任何自动化复用**：换一台机体要从头再来。

程序化基底的价值不在"省事"，在于它把**"第二台机体"的边际成本从 260 小时压到 30 小时**。这与 `mecha_render/能力评估报告.md` §6 实测的结论一致：第一个镜头 12 小时，第十个镜头 25 分钟。

而纯程序化的问题也已被实测钉死：路线 C 目前的产物仍是 2.5D 浮雕（体量门不合格，总厚 13.7% 机高）。**所以是"程序化打底 + 手工精修关键件"，不是二选一。**

### 5.3 为什么不用 AI 生成几何

三条独立理由，任一条都足够否决：

1. **范式冲突**：生成式输出的是"它认为该长这样"的形状，会平滑板缝、圆角锐角、对称化不对称——与"不能改动任何细节"直接互斥（`线稿转3D_方案与评审.md` §3.1）。
2. **本机跑不了**：TRELLIS.2 的 Mac 移植版要求 24 GB 统一内存、实测峰值 18 GB，本机 16 GB；Hunyuan3D 需 CUDA。这是实测阻塞，不是推测。
3. **参赛原创性**：生成模型的训练集里就有大量日系机甲，输出与既有 IP 的相似度无法保证。

可以用的地方只有两处：**三视图候选（出图不建模）**、**blockout 阶段的体量探索**。后者若想接进你的 agent 流水线，Meshy 5（$20/月）有官方 MCP server，是唯一能与现有自动化拼接的选项；Rodin Gen-2（Creator $24/月）硬表面几何质量更好但无 MCP；Tripo P1（$11.94 起）最便宜但偏卡通。

## 6 四条路线对比与选择

| 路线 | 内容 | 4 周可行 | 质量上限 | 现金成本 | 风险 |
|---|---|---:|---|---:|---|
| **R1 全自研** | 程序化 + Blender 全程手工 | **✗** 需 194–291 h | 风格化 PBR | ≈¥1,400（插件） | 工期必爆 |
| **R2 混合（推荐）** | 自研腿脚/腰/背包 + 外包 P0 三件（头/胸舱/座舱） | **✓** | 局部达 Unicorn 级 | ¥1,400 + 外包费 | 外包交期与原创声明 |
| R3 全外包 | 按《建模外包内容清单》A1–A7 整包 | ✓ | 可达 Unicorn 级 | 最高 | 报价与沟通成本、IP 条款 |
| R4 买套件 + 定制件 | 采购现成模块化身体 + 定制 A1/A2/A3 + A7 适配件 | ✓ | 中等（风格可能割裂） | 中 | 风格一致性；套件授权须可商用 |

### 6.1 选择：R2

理由：

1. **P0 三件（座舱 / 头 / 胸舱）恰好是外包清单里已经写好规格的部分**，交底材料现成，报价可比。
2. 腿脚 / 背包 / 腰裙是**视觉权重 7% 的部位**，程序化几何 + 法线细节足够，不值得外包。
3. R3 把全部质量押在外包方的原创声明上——`Unicorn包导入实测与差距评估.md` §6 已经写明，IP 复刻最坏结果是取消资格，这一条不能只靠合同。
4. R4 的风格割裂在 VR 里会被放大：玩家贴脸看的三处（座舱/头/胸）若与身体不是同一套造型语言，比"精度低一档"更致命。

**R2 的必要前提**：把 §2.1 的六条硬指标 + `Unicorn包导入实测与差距评估.md` §4.1 的 14 项座舱内构，一并写进外包交底。目前 `建模外包内容清单.md` 的 A8 贴图条款还是"5 张图/件、整机 ≤30 材质"，与 Unicorn 的"9 部位 × 3 通道"口径不同，需要对齐。

## 7 本机硬件现实

### 7.1 实测约束

| 项 | 值 | 影响 |
|---|---|---|
| 芯片 | Apple M4，10 核（4 性能 + 6 能效） | 建模与视口流畅，可接受 |
| 统一内存 | **16 GB** | 复杂场景吃紧：高模 + 4K 贴图 + 多图集同时驻留会触发交换 |
| 散热 | **无风扇** | 官网评测实测：Blender 渲染 8 分钟后过热降频，完成时间比有风扇的 Pro 慢 **22%**；30 分钟 4K 渲染机身 48 °C |
| macOS | 15.7.9 | 满足 Blender 5.x 的 macOS 13+ 要求 |
| 磁盘 | 181 GB 可用 | 够；但 4K 图集 + 中间文件增长快，建议留 30 GB 余量 |
| 参考基准 | Blender "Party Tug" 场景渲染 **1 分 48 秒**（M4 Air） | 这是轻量场景；我们的资产是 375 件 / 377k 面量级，量级不同 |

### 7.2 规避方式

| 风险 | 规避 |
|---|---|
| 无风扇降频 | **视口用 EEVEE 不用 Cycles**；只在交付前跑少量 Cycles 静帧；长任务放夜里连续跑，接受 20% 降速 |
| 16 GB 吃紧 | **图集化**（4 张 2K 而不是 81 张 4K）；高模与低模分文件；关掉 Blender 的"自动打包贴图" |
| 烘焙慢 | 按件烘焙而不是整机烘焙；Normal/AO 用 1K 试跑确认参数，再切 2K 正式烘 |
| 无外接显卡 | 不做 GPU 光线追踪预览；景深/运动模糊放到 Unity 后期 |

### 7.3 关于把重计算 offload 到 Oracle ARM 服务器

你在 Oracle 云有一台 ARM 实例（217.142.246.70，Ubuntu 24.04 aarch64），直觉上适合跑无人值守的烘焙与渲染。但有一个必须先验的阻塞：

> **Blender 官方下载页当前只提供 Linux x64（367 MB），没有 Linux ARM64 构建**（Windows ARM 有，Linux ARM 没有）。

所以这条路要成立，只有两个前提之一：① 发行版源（Ubuntu 的 `blender` 包）提供 aarch64 构建，且版本 ≥ 4.x；② 自行编译（成本远超收益）。**建议：等中模阶段真正感到烘焙慢时，花 20 分钟在服务器上 `apt install blender` 验一次；验不过就放弃，不要在选型阶段把它算进方案。**

**购买顺序的建议（重要）**：

## 10 与现有工程的对接

### 10.1 契约表是唯一的接口

建模软件里必须**先建好空物体层级，再往里放几何**，而不是建完几何再补空物体。原因是 `Contracts/尺寸与接口契约表.md` 明确规定：

> 命名固定，代码按名查找，**不允许改名**。

所以 Blender 里的结构应当长这样（与 Unity 侧一一对应）：

```
ArtRoot
├── Pivot_CockpitRoot          (0, 11.40, 0)
│   ├── Cockpit_Floor          y = 10.40
│   ├── Seat_Base              y = 10.85（坐面 0.45 离地板）
│   ├── SeatAnchor             y = 11.55  ← 相机锚点
│   ├── Pivot_StickBase        (+0.30, 10.75, +0.55)  轴向 X
│   ├── Pivot_Throttle         (−0.30, 10.75, +0.55)  轴向 X
│   └── ...
├── Pivot_Hatch_L / _R         铰链在左缘，轴向 Y，0–95°
├── Pivot_Elbow_R              (0, 11.20, 0)  轴向 X
├── Pivot_Wrist_R              (0, 8.00, 0)   轴向 XYZ
└── Pivot_Skirt_Front / _Side_L / _R
```

导出 FBX 时勾选 **"Include > Object Types > Empty"**，否则空物体不导出，Unity 侧按名查找会全部落空——这是最容易犯、又最难查的一个错。

### 10.2 与 `mecha_render` 的分工

| 层 | 归属 | 理由 |
|---|---|---|
| 构造逻辑（距离场基底、板壳拟合、剪影约束） | **移植进 Blender Geometry Nodes** | 保留"改一处全机跟随"的杠杆 |
| 分镜 / 运镜 / HUD / 程序化配乐 | **留在 `mecha_render`** | Python 命令行流水线已跑通，成片 121 秒，边际成本极低 |
| 材质 / 贴图 / 枢轴 / LOD | **Blender + Painter** | 这是 Python 管线结构性做不到的三件事 |
| 实时交互 | **Unity** | 不变 |

不要试图把 `r3d.py` 的软件光栅化器升级成 PBR 渲染器——`能力评估报告.md` §3.2 已判定这是结构性缺失（需 BRDF + 环境贴图，工作量翻倍），而 Blender 免费提供。

### 10.3 材质口径对齐（避开 Unicorn 的坑）

| 项 | Unicorn（错的方式） | 我们（对的方式） |
|---|---|---|
| Shader | 25 个全 `Standard`（Built-in） | 全部 `Universal Render Pipeline/Lit` |
| 贴图通道 | COL + BUMP + SPEC 三张独立文件 | BaseColor + Normal + **打包的** MetallicGloss(A) + AO |
| 导入结果 | URP 下整机洋红 | 直接可用 |
| 材质数量 | 25 个内嵌 prefab（只落地 1 个 .mat） | ≤ 30 个独立 .mat 资产，可批量替换 |

**验收判据（写进外包验收清单）**：导入 Unity URP 后，随机抽 5 个材质，`Shader` 必须是 `Universal Render Pipeline/Lit`，且 `_BaseMap` / `_BumpMap` 非空。这条比"看截图"可靠。

### 10.4 验收门禁接现有脚本

| 门 | 命令 | 通过标准 |
|---|---|---|
| 编译门 | `Tools/compile-check.sh` | 23 脚本 0 error（资产导入后必须重跑） |
| 尺寸门 | 在含 1.75 m 人体参考的场景里量 | 误差 ≤ 2 cm（`建模外包内容清单.md` §5 第 1 项） |
| 枢轴门 | 录屏演示每个 `Pivot_*` 的旋转 | 位置与轴向正确，不接受截图 |
| 命名门 | 脚本比对契约表 | 7 个 `Pivot_*` 全部命中，0 缺失 |
| 性能门 | Unity Profiler | 整机 DC ≤ 200，三角 ≤ 500k |
