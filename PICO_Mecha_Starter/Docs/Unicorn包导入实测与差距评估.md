## 1. 结论

**几何够用，材质与工程结构全部不可用。直接拖进我们的 URP 工程，看到的是一片洋红。**

| 维度 | 实测 | 我们的要求 | 差多远 | 可修 |
|---|---|---|---|---|
| 三角面 | 377,328 | ≤ 900,000 | **在预算内（占 42%）** | 不需要修 |
| 渲染管线 | 材质全为 Built-in `Standard` | URP 14 | **阻塞：URP 下整机洋红** | 可修，1–2 天 |
| 材质通道 | 只有 albedo，法线/高光**全丢** | COL+BUMP+SPEC 三图 | **严重：装甲无凹凸、无金属感** | 可修，需重挂 54 张贴图 |
| Draw Call | 375 个独立 Mesh（375 SubMesh） | ≤ 200 | **超 1.9×，移动 XR 不可接受** | 可修，1–2 天合批 |
| 层级 | 375 个**平级**子对象，最大深度 1，名字长达 60 字符 | `ArtRoot` 下按 `Pivot_*` 命名 | **阻塞：无法按契约定位任何关节** | 可修，1 天（命名有语义，可脚本化） |
| 骨架 | 0 个 SkinnedMeshRenderer | 抓杆、受击、舱门开合 | **阻塞：完全静态** | 工作量大，3–6 周 |
| 尺度 | 需缩放 **0.063936**，脚底还在 **−0.31 m** | 1 unit = 1 m，脚底 y=0 | 小，一个数字 | 5 分钟 |
| 肩宽 | 10.20 m（按身高缩放后） | 10.60 m | 比例差 3.8%，**改不了**（二选一：按身高 or 按肩宽对齐） | 不可修，只能接受或换模型 |
| 座舱 | 内构中心 ≈ **14.0 m（77% 身高）** | 11.40 m（62.6%） | **我们的座舱比真实 MS 低 2.6 m** | 这是**契约**的选择，不是模型的问题 |

**一句话**：这个包不能当 `ArtRoot` 用，但它是一份**带真实内构比例的高质量参照**——顺手把我们的契约解剖位置照出了问题。

## 3. 导入器给出的实际结果

### 3.1 结构

| 项 | 值 | 说明 |
|---|---|---|
| GameObject 总数 | 376 | 1 根 + 375 个子对象 |
| **最大层级深度** | **1** | **全平铺，没有任何嵌套** |
| MeshFilter | 375 | 每件一个独立 Mesh |
| SkinnedMeshRenderer | 0 | 无骨架、无蒙皮权重 |
| 唯一 Mesh | 375 | 无共享，无法 GPU Instancing |
| SubMesh 总数 | 375 | 每个 Mesh 恰好 1 个 SubMesh |
| 顶点总数 | 218,438 | 三角 377,328，平均每件 1,006 面 |

导入器设置全为默认：`globalScale 1`、`useFileScale True`、`importNormals Import`、`isReadable False`、`materialLocation InPrefab`、`weldVertices True`。

`materialLocation = InPrefab` 的后果：25 个材质**内嵌在 prefab 里，只落地 1 个 .mat 资产**。想统一换材质得逐个 prefab 内部改，这是后续维护的坑。

### 3.2 名字为什么这么长

OBJ 里每个对象先写 `g default`，再写一行把祖先路径拼起来：

```
g default
g head_assy_G main_assy_G UNICORN_GUNDAM_MOD_G face_mask face_unicorn_mode_G
```

Unity 取最后一段当对象名，于是得到 `head_assy_G_main_assy_G_UNICORN_GUNDAM_MOD_G_face_mask_face_unicorn_mode_G` 这种 60 字符的名字。**层级信息在名字里，不在 transform 树上。**

### 3.3 尺度

| 项 | 值 |
|---|---|
| 原始包围盒 | 159.60 × 284.66 × 100.13（单位不明） |
| 原始底面 Y | −4.92 |
| 缩放到 18.20 m 的系数 | **0.063936** |
| 缩放后 | 18.20 × **10.20** × 6.40 |
| 落地所需偏移 | +0.31 m（否则机甲沉进地面） |

系数不是 0.01（cm）也不是 1/1000（mm），说明**原始单位无物理含义**，只能按目标高反推。反推后肩宽 10.20 与我们契约的 10.60 差 0.40 m——**这个差值改不了**：按身高对齐就必然肩宽偏窄，按肩宽对齐就必然身高超 18.2。

### 3.4 材质

| 项 | 值 |
|---|---|
| 材质数 | 25 |
| Shader | **全部 `Standard`（Built-in）** |
| 有 albedo | 24 / 25（`blinn20SG` 无贴图） |
| 有法线贴图 | **0 / 25** |
| 有高光/金属贴图 | **0 / 25** |
| 贴图总数 | 81 张（9 部位 × 白/红/其它 × COL/BUMP/SPEC） |
| 实际被用上 | **27 张 COL**，其余 54 张 BUMP/SPEC 被丢弃 |

内置 OBJ 导入器只认 `map_Kd`，MTL 里的 `bump` 与 `map_Ks` 它不接受。所以这个资产本来是标准 PBR 三图，进 Unity 后**退化成一图**。

### 3.5 URP 实测（决定性）

在 URP 14.0.12 工程里渲染同一份资产：

| 项 | 值 |
|---|---|
| 当前管线 | `UniversalRenderPipelineAsset` |
| 材质 Shader | `Standard` |
| 渲染结果 | **整机纯洋红，无任何贴图** |

见 `Docs/参照/unicorn/10_urp_front.png`。这就是「直接拖进我们项目」的确切结果。

### 4.2 顺手照出的契约问题

把这个座舱与我们 `MechaContract` 对齐：

| 量 | 契约 | 本模型（落地后） | 差 |
|---|---|---|---|
| 舱地板 | 10.40 | 脚踏 13.48 | **+3.08** |
| 座面 | —（无此概念） | 13.47 | — |
| 眼位 | 11.55 | 座面 +0.75 ≈ 14.2 | **+2.65** |
| 座舱中心 | 11.40（62.6% 身高） | ≈ 14.0（**77%**） | **+2.6** |
| 舱顶 | 12.40 | 舱门顶 14.92 | +2.52 |
| 座舱内腔高 | 2.00 | 球形舱 ≈ 1.13 | −0.87 |

**我们的座舱比真实 MS 低约 2.6 m，也就是压在腹部上缘而不是胸口中部。**

这不是代码 bug（契约自洽，`Validate()` 通过），是一个可以讨论的设计取舍：座舱低 → 主窗更容易被胸甲遮住上限、沉浸感更「闷」；座舱高 → 更接近独角兽的真实解剖，视野更开阔。

**建议不改**，但在门 1 验收（README §8）时加一条自问：「眼位 11.55 看起来像坐在腹舱还是胸舱？」如果要动，优先调 `chestSocketY` 与 `shoulderY` 这两个数，白盒会自动跟。

## 5. 修到「能进我们项目」要多少工

| 阶段 | 工作 | 工期 |
|---|---|---|
| A. 能看见 | 25 个材质全换 URP/Lit，重挂 54 张 BUMP/SPEC，校正 0.063936 缩放与 +0.31 落地 | **1–2 天** |
| B. 能跑 | 按部位重挂层级到 `ArtRoot`（375 件按名字自动分类，脚本可做）+ 静态合批把 375 DC 压到 ≤200 | **2–3 天** |
| C. 能交互 | 抓杆/受击/舱门开合/登机——分件刚体动画，不需要骨架 | **3–5 天** |
| D. 能动画 | 走路、挥剑、变形——需要骨架 + 蒙皮权重（377k 面），外包 | **3–6 周** |

到 B 结束（约 1 周），它就是一个**符合契约尺寸的静态外观**；到 C（约 2 周）能当「可交互载具」；D 是另一个量级的项目。

对比：外包一支「按契约做好 ArtRoot + 3 档 LOD」的报价，和这一个半星期的改造工，值得先问价再决定。

## 6. 必须先说清的事

这是**万代《机动战士高达 UC》独角兽高达**的第三方模型（Unicorn / The Origin 系列）。已在上一轮核验中确认：

- 作**结构参照**（比例、截面深宽比、内构布局）属行业常规，不构成问题；
- 但**PICO 参赛提交物不得直接使用或明显衍生其几何与贴图**——赛题要求原创，且 IP 复刻最坏结果是取消资格；
- 因此本包的定位只能是：**内部参照 + 建模交底素材**，不能出现在任何对外交付物里。
