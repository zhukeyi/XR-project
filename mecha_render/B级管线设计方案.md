# B 级画质管线 · 完整设计方案

> 目标：把 `mecha_render` 从「A 级概念演示」推进到「B 级番剧单镜头」
> 前置基线：v3 成片（12s / 1280×720 / 1,720 多边形 / 每帧 410 ms）
> 方案日期：2026-11-06

---

## 1 结论与路线选择

**核心结论：B 级不需要换技术栈，需要换渲染架构。** 从「画家算法 + 每面平涂」换成「z-buffer + G-buffer 延迟着色」，一次性解决四个问题——排序穿模、平涂无渐变、无贴图、无逐像素光照。真实基准测试显示 B 级目标配置单帧 712 ms，288 帧约 4 分钟，成本可接受。

三条候选路线的实测对比：

| 路线 | 画质上限 | 开发量 | 单帧成本 | 结论 |
|---|---|---|---|---|
| **A. 现有管线加参数** | 提不上去 | 1 天 | 410 ms | 否决——根因是架构不是参数 |
| **B. 重构为 G-buffer 延迟着色** | 番剧单镜头 | 8–12 天 | 712 ms | **选定** |
| **C. 转 Blender/UE5** | 电影级 | 30+ 天（含学习） | 30–200 ms（需 GPU） | 本项目硬件不满足，且丧失可自动化性 |

**不选 C 的理由**：本机无独显，UE5 Lumen 跑不动；更关键的是本次已实测出本方案的最大价值——**代码即资产、参数化批量产出**。转引擎会把「改一行参数重渲 2 分钟」变成「打开工程手动改 2 小时」。

## 2 差距根因（逐条对着现有代码）

不是凭感觉列的，是对着 `r3d.py` 的实际实现逐项找的：

| # | 现象 | 代码层根因 | 位置 |
|---|---|---|---|
| 1 | 装甲表面是纯色平涂，无明暗过渡 | `cel_shade()` 是 **per-face** 调用，一个多边形一个常量色；法线是面的法线，不是顶点法线 | `r3d.py:305` `collect()` 第 288 行 `out.add(pts, mat.rgb, ...)` |
| 2 | 无法贴图 | `Tris` 只有 `pts/cols/emis/cens/nrms`，**没有 UV 通道**；`Mat` 只有 `rgb/emissive/rim/spec`，没有纹理槽 | `r3d.py:237` `class Tris`、`r3d.py:207` `class Mat` |
| 3 | 近景可见棱面（圆柱是 7–10 边多边形） | `g_tube(sides=8)` 默认 8 边，且侧面为独立 quad，法线不做平滑 | `r3d.py:103` |
| 4 | 甲片边缘是硬切角，没有倒角高光 | `g_box` / `g_wedge` 只有 8 顶点，无倒角环 | `r3d.py:89` `g_box` |
| 5 | 排序穿模（大面压小面） | 画家算法按面中心 z 排序，**相交或套叠的面必然排错** | `r3d.py:render()` `order = np.argsort(-cam_cen[:,2])` |
| 6 | 抗锯齿靠超采样硬扛 | 无 MSAA，只有 ss=2 降采样 | `Renderer(ss=2)` |
| 7 | 无景深 / 无运动模糊 / 无环境光遮蔽 | 后期只有速度线、光束、星芒、白闪 | `film2.py:post_fx()` |
| 8 | 光照不含高光 | `cel_shade` 里 `spec` 参数存在但**从未被使用** | `r3d.py:208` `Mat.spec`、`r3d.py:305` 函数体 |

第 8 条特别值得说明：`Mat` 定义了 `spec` 字段，但 `cel_shade()` 的签名里根本没有它。这是半成品痕迹，说明当初就预留了升级口。

## 3 一个关键判断修正：不需要骨骼蒙皮

上一版评估报告把「骨骼蒙皮」列为 B 级必需项。**深入代码与题材后，这个判断需要修正。**

理由有三：

1. **硬表面机甲在物理上就是刚性分块**。真实装甲板不会随关节弯曲而变形，只会**滑动、旋转、错位**。当前「每块甲片独立成件、挂在关节节点下」的建模方式，恰恰是硬表面的正确做法。
2. **蒙皮解决的是软体形变**——肌肉、布料、面部。这些本管线根本不做。
3. **276 个部件、1720 面已全部挂在节点树上**，节点旋转即可带动子部件。这是「刚性绑定」，对机甲是足够的。

**真正缺的不是蒙皮，是「装甲联动」**：当膝盖弯曲 90° 时，小腿甲要相对大腿甲**滑动避让**，否则穿模。这个用「关节约束 + 位移补偿」就能解决，成本远低于蒙皮（约 1/5 工作量），效果对硬表面反而更正确。

**修正后的结论**：B 级的差距集中在【渲染架构 + 材质 + 几何密度 + 后期】四块，**动画层是加分项不是必需项**。这大幅降低了工期估算。

## 4 目标架构

五层，从下往上。**关键设计原则：逐面循环只允许出现在光栅化，所有逐像素计算必须全屏一次向量化。**

```
┌─────────────────────────────────────────────────┐
│  L5 后期  SSAO · DoF · MotionBlur · ACES · Flare │  ~120 ms
├─────────────────────────────────────────────────┤
│  L4 着色  延迟着色：PBR+赛璐璐混合 · 法线贴图      │  ~35 ms  ← 全屏向量化
├─────────────────────────────────────────────────┤
│  L3 材质  程序化贴图生成 · UV 图集 · 切线空间      │  离线一次性
├─────────────────────────────────────────────────┤
│  L2 光栅  z-buffer · G-buffer · 透视校正插值      │  ~450 ms ← 逐面循环（唯一瓶颈）
├─────────────────────────────────────────────────┤
│  L1 几何  倒角图元 · 平滑法线 · UV/切线 · LOD      │  ~30 ms
└─────────────────────────────────────────────────┘
```

## 5 子系统设计

### 5.1 L2 光栅化层：画家算法 → z-buffer + G-buffer

**这是整个方案的地基，必须先做。**

当前 `render()` 的循环结构是「排序 → 逐面投影 → 逐面着色 → PIL 画 polygon」。改为两阶段：

**阶段 A：几何光栅化（写 G-buffer）**

| G-buffer 通道 | 类型 | 用途 |
|---|---|---|
| `depth` | float32 | z 测试、SSAO、景深 |
| `normal` | float32 ×3（view space） | 光照、法线贴图基底、SSAO |
| `uv` | float32 ×2 | 贴图采样 |
| `tangent` | float32 ×3 | 法线贴图转换到世界空间 |
| `matid` | int16 | 材质参数查表（4 种基础材质 + 发光体） |
| `wpos` | float32 ×3（可选） | 世界坐标，用于环境反射 |
| `faceid` | int32 | 调试与描边（可判断相邻像素是否同面） |

**关键技术点**

1. **透视校正插值**：屏幕空间的重心坐标不能直接插值 UV/z，必须除以 w。公式 `attr = Σ(wi · attrᵢ / zᵢ) / Σ(wi / zᵢ)`。这一步不做，贴图会有明显的透视扭曲。
2. **四边形三角化**：现有 1590 个四边形按扇形拆成 2 个三角形，得到 3,976 三角。四边形的非平面性（`g_plate` 挤出的侧面可能是非平面四边形）用对角线拆分自动处理。
3. **近平面裁剪**：现有 `_clip_near()` 是 2D Sutherland–Hodgman，可直接复用，输出三角形后重新三角化。
4. **像素中心偏移**：`+0.5` 采像素中心，避免半像素偏移。
5. **保留 PIL 路径用于背景**：城市、天空仍走现有 `sky()` + `dr.polygon()`——它们面数多但无细节需求，走 G-buffer 是浪费。**前景机甲走新管线，背景走老管线**，最后合成。这是性能上的关键权衡。

**不做的事**：不做真正的 MSAA（4 个子样本 × 4 倍存储）。沿用 ss=2 超采样 + 后期边缘检测描边，实测已足够，且实现成本为零。

### 5.2 L3 材质层：程序化 PBR 贴图

**这是画质提升感知最强的部分**，比几何密度重要。

**核心决策：贴图用代码生成，不引入手绘美术资源。** 理由：保持「代码即资产」，且用户无美术资源；程序化贴图对机甲这种**规整人造物**效果极好（面板线、铆钉、编号、磨损都可以算法生成）。

**贴图图集设计**（单张 2048×2048，RGBA 打包）

| 通道 | 内容 |
|---|---|
| R | BaseColor 亮度 |
| G | Roughness |
| B | Metallic |
| A | 细节遮罩（面板线 / 铆钉 / 编号区） |

实际实现用**两张图**更清晰：
- `albedo.png`（2048² RGB）：白 / 蓝 / 红 / 深灰 四个 1024×1024 区块，各自带细节
- `normal.png`（2048² RGB）：由高度图求 Sobel 梯度生成

**四种基础材质的程序化生成规则**

| 材质 | 生成方式 |
|---|---|
| **装甲白** | 底色 0.94 白 → 叠加 0.02 幅度的柏林噪声（模拟涂装不匀）→ 面板分割线（1px 深灰，按网格随机断开）→ 边缘磨损（距边 2px 内混入深灰）→ 少量油渍斑点 |
| **装甲蓝** | 同上，底色替换；磨损更重（蓝漆附着力差于白漆，视觉上更真实） |
| **警示红** | 底色 + 强磨损（红色区域在设定里是高频接触部位） |
| **骨架深灰** | 底色 0.23 + 金属拉丝纹（单向噪声）+ 油污积垢（低频噪声压暗） |

**编号 / 队徽喷字**

用 PIL 的 `ImageFont.truetype`（本机有 `PingFang.ttc` / `Helvetica.ttc`）在贴图上渲染 "HX-07"、番号、警示三角符号，然后：
1. 用噪声做 alpha 遮罩，模拟喷漆不匀（边缘羽化 + 随机剥落）
2. 叠一层极淡的阴影偏移，做出「喷在曲面上」的厚度感

**法线贴图生成**

1. 先生成**高度图**：面板线处高度 −2px，铆钉处 +1px，边缘倒角处线性过渡
2. 对高度图做 Sobel 求梯度 `(dx, dy)`
3. 转切线空间法线：`N = normalize(-dx·s, -dy·s, 1)`，再编码到 0–255

**UV 展开策略**

不做真正的自动展开（那是大工程）。采用**每图元手工指定 UV 区域**：
- `g_box` 的 6 个面各映射到图集的一个区块（用 box 的局部坐标生成 UV，天然无缝）
- `g_tube` 侧面按 `(i/sides, y)` 参数化，接缝在背面（不可见）
- `g_plate` 侧面按轮廓弧长参数化
- 每个 Node 可覆写 UV 偏移/缩放，实现「同一张贴图的不同区域」

这样不需要 UV 展开器，且接缝位置可控。

### 5.3 L1 几何层：倒角 + 平滑法线

**目标面数：8,000–12,000 三角**（当前 3,976）。**提升靠倒角而非细分**。

| 新图元 | 取代 | 面数变化 | 作用 |
|---|---|---|---|
| `g_rbox(w,h,d,bevel)` | `g_box` | 6 → 26（每面 + 4 个倒角 quad + 8 个角三角） | 甲片边缘有倒角高光线，这是"金属感"的来源 |
| `g_stube(r0,r1,h,sides,cap_bevel)` | `g_tube` | sides 8→14，光滑法线 | 圆柱近景不再见棱 |
| `g_lathe(profile, sides)` | 手工堆叠的头部/肩甲 | 可控 | 旋转体，做头部壳、肩球、喷口内壁 |
| `g_hexplate` | `g_plate` | 同 | 带倒角的翼板 |

**倒角的画质收益**：倒角面法线与主面不同，赛璐璐分级后会落在不同的明度档，天然产生一条亮边——**这一条线就是"金属 vs 塑料"的视觉分界线**。当前版本甲片是硬切角，所以看起来像塑料积木。

**平滑法线规则**
- 同一图元的相邻面在同一平滑组 → 顶点法线取平均
- 硬边（倒角转折处）→ 拆顶点，法线不共享
- 实现：在 `collect()` 里给每个顶点预计算法线累加器，按 `smooth_group` 决定是否合并

**LOD**：远景（>40 m）图元自动降级为无倒角版本，面数减半。

### 5.4 L4 着色层：PBR + 赛璐璐混合

**关键设计：不做纯 PBR，做「赛璐璐骨架 + PBR 皮肤」。** 番剧质感的核心是分明的明暗交界线，纯 PBR 会把它磨平。

**着色公式（逐像素）**

```
1. 基础法线    n = normalize(N_geo + TBN · N_map · strength)
2. 漫反射      lambert = saturate(dot(n, L_key))
3. 赛璐璐量化  lam_q = quantize(lambert, LEVELS)      ← 保留 5 档
4. 软过渡      lam_s = lerp(lam_q, lambert, 0.35)      ← 关键：不完全量化
5. 材质        albedo = tex(albedo, uv) · base_color
6. 高光        spec = pow(saturate(dot(n, H)), shininess) · metallic
7. 环境        env = lerp(ambient, skycolor(n), 0.5)
8. 边缘光      rim = pow(1 - saturate(dot(n, V)), 3) · rim_color
9. 合成        col = albedo·(lam_s·L + env) + spec·C_spec + rim
10. 色调映射   ACES 近似
```

第 4 步的 `lerp(量化值, 连续值, 0.35)` 是画质的关键调节旋钮：
- 100% 量化 → 纯赛璐璐（当前效果，硬边但假）
- 0% 量化 → 纯 PBR 软光（真实但失去动画感）
- 35% → 交界线仍清晰，但两侧有微妙渐变（番剧实际做法）

**为什么不直接用量化值**：番剧在 TV 尺寸下能看清，但在 1080p 大屏上纯量化会产生「色阶断层」（banding），因为 5 档亮度跨度太大。掺 35% 连续值刚好消掉断层又保住分界线。

### 5.5 L5 后期层

| 效果 | 实现 | 成本 |
|---|---|---|
| **SSAO** | 深度 + 法线，8 方向 × 2 步采样，半径 0.5 m | ~40 ms |
| **景深** | CoC = `abs(1/z - 1/focus)`，3 层可变半径高斯 | ~50 ms |
| **运动模糊** | 用上一帧相机矩阵重投影当前深度，沿速度矢量做 8 抽样方向模糊 | ~30 ms |
| **ACES 色调映射** | 有理函数近似，纯 numpy | ~5 ms |
| **色彩分级** | 三通道曲线 + 阴影偏青/高光偏暖（分离色调） | ~5 ms |
| **变形宽银幕光晕** | 亮部阈值提取 → 横向拉伸模糊 → 加色 | ~20 ms |
| **胶片颗粒** | 固定种子噪声，振幅 2/255 | ~3 ms |

**景深是"电影感"的第一杠杆**。当前画面全清晰，读起来像游戏截图；加了景深（对焦在机体胸部，背景城市虚化）立刻变电影。

**运动模糊是"速度感"的第一杠杆**。S5 挥砍镜头当前靠手绘速度线，有了真实运动模糊后速度线可以减半，观感提升明显。

### 5.6 音频层（与用户历史经验对齐）

| 升级项 | 现状 | 目标 |
|---|---|---|
| 混响 | 简易延迟 | 卷积混响（合成 IR：指数衰减噪声 × 早期反射） |
| 空间化 | 无 | 左右声道按画内位置做 pan + 距离衰减 |
| 分层 | 单轨合成 | 底噪 / 机械 / 推进 / 音乐 四层可独立混音 |
| 动态 | 无压缩 | 软拐点压缩器（阈值 −12 dB，比 4:1） |

## 6 性能预算（全部来自实测，非估算）

### 6.1 实测基准

测试环境：本机 CPU 单核，1280×720 与 2560×1440 与 3840×2160，真实机体几何。

| 配置 | 三角数 | 渲染分辨率 | 光栅化 | 单三角成本 |
|---|---|---|---|---|
| 现状 | 3,976 | 1280×720 | 100 ms | 25.2 μs |
| 现状 | 3,976 | 2560×1440 | 156 ms | 39.3 μs |
| B 级 | 11,928 | 2560×1440 | 448 ms | 37.5 μs |
| B 级 | 11,928 | 3840×2160 | 712 ms | 59.7 μs |
| 逐像素着色 | — | 12.7 万 px | **6 ms** | 全屏向量化 |

### 6.2 关键发现

**分辨率几乎免费，面数才是钱。**

- 分辨率翻 4 倍（720p→1440p 超采样），光栅化只涨 56%（100→156 ms）
- 三角数翻 3 倍（3,976→11,928），光栅化涨 187%（156→448 ms）
- 逐像素着色的成本与像素数几乎无关（12.7 万像素仅 6 ms）

原因：大部分三角形的屏幕包围盒很小（实测中位数仅 127 px），numpy 的固定开销主导了单三角成本，而不是像素填充。

**这条结论直接决定了设计取向**：应该「少面数 + 高精度着色 + 高分辨率」，而不是「多面数 + 低精度」。这正好与赛璐璐风格契合——赛璐璐本来就不需要高模。

### 6.3 单帧预算表

| 阶段 | 成本 | 备注 |
|---|---|---|
| L1 几何收集 | 30 ms | 276 部件 → 1.2 万三角 |
| L2 光栅化（前景） | 448 ms | **唯一瓶颈** |
| L2 光栅化（背景城市） | 60 ms | 沿用 PIL 画家算法 |
| L3 贴图采样 | 8 ms | 双线性，12 万像素 |
| L4 逐像素着色 | 27 ms | 含法线贴图、spec、rim |
| L5 后期全套 | 153 ms | SSAO+DoF+MB+ACES+Flare |
| HUD 与字幕 | 15 ms | 沿用现有 |
| **合计** | **741 ms** | 目标配置 1080p ss=2 |
| **288 帧全片** | **3.6 分钟** | |
| **1440 帧（60 秒片）** | **18 分钟** | |

### 6.4 优化储备（如需要再快）

| 手段 | 预期收益 | 代价 |
|---|---|---|
| 背面剔除前移到三角化之前 | −35% 光栅化 | 无 |
| 按屏幕 tile 分块剔除（16×16） | −25% 光栅化 | 中等复杂度 |
| 包围盒预筛 + 小三角合并 | −15% | 低 |
| 多进程分帧渲染（`multiprocessing`） | ÷ 核数 | 无（帧间独立） |
| 前景/背景分层并行 | −10% | 低 |

**最值得做的是多进程分帧**：288 帧完全独立，8 核可压到 30 秒。这条几乎零风险。

## 7 实施阶段

每阶段独立可交付、可验证、可回退。**不做大爆炸式重写。**

### M1 · 地基（3–4 天）：G-buffer 光栅化

| 交付 | 内容 |
|---|---|
| `gfx/gbuffer.py` | z-buffer 光栅化，输出 depth/normal/uv/faceid |
| `gfx/shade.py` | 最小可用延迟着色（复刻现有赛璐璐效果） |
| 验收 | 输出与 v3 逐像素对比，**结构一致、无穿模**；单帧 ≤ 800 ms |
| 回退 | 保留 `r3d.py` 不动，新模块独立 |

**M1 的关键价值不是画质，是消除穿模**。当前画家算法在 S5 挥砍（手臂交叉躯干）时必然有排序错误，只是 720p 加暗色掩盖了。

### M2 · 材质（3–4 天）：程序化贴图

| 交付 | 内容 |
|---|---|
| `gfx/texgen.py` | 四种基础材质的 albedo / normal / roughness 生成 |
| UV 生成 | 各图元的参数化 UV + 图集映射 |
| 验收 | 1080p 单帧放大 4 倍，能看清面板线、编号喷字、边缘磨损；法线贴图在倒角处产生连续高光 |
| 回退 | 可全局开关 `use_texture=False` 退回纯色 |

**这是感知最强的阶段**。贴图一上，画面立刻从「色块拼装」变「有机体」。

### M3 · 几何（2–3 天）：倒角与平滑

| 交付 | 内容 |
|---|---|
| `core/prim.py` | `g_rbox` / `g_stube` / `g_lathe` + 平滑法线分组 |
| 机体重标 | 关键甲片（头、胸、肩、小腿、脚）换用倒角图元 |
| 验收 | 甲片边缘有 ≥2 px 倒角高光线；圆柱近景棱面消失；面数 ≤ 1.2 万 |
| 回退 | 图元按名替换，可逐部件回退 |

### M4 · 后期（2–3 天）：电影感

| 交付 | 内容 |
|---|---|
| `gfx/post.py` | SSAO / DoF / MotionBlur / ACES / 分级 / Flare |
| 验收 | 景深：对焦面外 CoC ≥6 px；运动模糊：挥砍帧方向模糊长度 ≥8 px；SSAO：装甲缝隙可见暗部 |
| 回退 | 各效果独立开关 |

**M4 是性价比最高的阶段**——不加一个多边形，纯后期就能把观感拉高一个档。

### M5 · 动画增强（2 天，可选）

| 交付 | 内容 |
|---|---|
| `anim/rig.py` | 关节限位 + 装甲联动补偿 |
| `anim/secondary.py` | 裙甲/背包翼板的弹簧-阻尼跟随 |
| 验收 | 膝盖 90° 弯曲无穿模；急停时裙甲有滞后摆动 |

### 总工期

| 阶段 | 工期 | 累计 |
|---|---|---|
| M1 地基 | 3–4 天 | 4 天 |
| M2 材质 | 3–4 天 | 8 天 |
| M3 几何 | 2–3 天 | 11 天 |
| M4 后期 | 2–3 天 | 14 天 |
| M5 动画 | 2 天 | 16 天 |

**M1–M4 完成即达 B 级，14 天。** M5 是锦上添花。

## 9 验收标准（可量化，不靠"看着像"）

B 级不是主观判断，定六个可测指标：

| # | 指标 | 测量方法 | 通过线 |
|---|---|---|---|
| 1 | **明暗层次** | 取机体表面 20 个采样点，相邻像素亮度差的标准差 | ≤3.0（无量化台阶） |
| 2 | **贴图可见度** | 1080p 帧放大 4 倍，目视 + 边缘检测计数 | 面板线 ≥8 条、编号 ≥1 处 |
| 3 | **倒角高光线** | 装甲边缘的亮度梯度峰值宽度 | ≥2 px |
| 4 | **深度正确性** | 逐帧检查手臂与躯干交汇处的 `faceid` 连续性 | 穿模帧 = 0 |
| 5 | **景深** | 背景区域边缘梯度宽度的均值 | ≥6 px（对焦面 ≤2 px） |
| 6 | **运动模糊** | 挥砍帧沿速度矢量的方向模糊长度 | ≥8 px |

前三条由新的 `tools/qc.py` 自动检测，后三条人工抽帧核对。**每次改动后跑一遍，形成回归基线。**

## 10 风险与退路

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| G-buffer 透视校正写错导致贴图扭曲 | 中 | 高 | M1 阶段先用棋盘格贴图验证；有现成公式可对照 |
| 面数超 1.5 万导致单帧 >1.5 s | 中 | 中 | LOD + 背面剔除前移；多进程分帧兜底 |
| 倒角图元引入法线错误（非平面四边形） | 中 | 中 | 倒角面全部三角化；用现有"外法线定向"规则校验 |
| 程序化贴图看起来"脏"而非"旧" | 中 | 中 | 噪声幅度分材质调参；先做白装甲（最宽容）再推广 |
| 14 天工期超期 | 中 | 中 | M1–M2 完成即有明显提升，可在此截断交付 |
| 纯 Python 迭代太慢影响创作节奏 | 低 | 高 | 保留 `still` 模式：单帧 0.8 s 可接受；预览用 720p ss=1（0.15 s） |

**最重要的退路**：`r3d.py` 全程不删。任何阶段出问题，切回 v1 立刻能出片。v3 成片 `steel_spine_v3.mp4` 作为画质基线永久保留。

## 11 决策依据：什么情况选哪条路

| 场景 | 选择 | 理由 |
|---|---|---|
| 内部概念验证、参赛 pitch、投标动效 | **现有 A 级管够** | 成本 0，已交付 |
| 需要「产品级」单镜头、对外宣传片 | **B 级（本方案）** | 14 天，本地可跑，无 GPU 依赖 |
| animatic / 动态分镜稿交给外包 | **B 级** | 参数精确，外包沟通成本最低 |
| 正式 TVC、上星播出 | **UE5 + 外包精模** | B 级仍有贴图精度与光照真实度上限 |
| 需要大量变体（50 个不同机体） | **B 级压倒性优势** | 改参数批量渲，UE 做不到 |

## 12 一句话总结

> B 级 = **把「画家算法 + 每面一个颜色」换成「z-buffer + G-buffer + 逐像素着色」，再补程序化贴图、倒角几何、电影后期**。架构换一次，其余三块都是加法。实测 14 天、单帧 741 ms、1080p 可跑在本机单核上。
