# 程序化伪 3D 渲染 · 能力评估报告

> 评估对象：`mecha_render` 管线（纯 Python + numpy + PIL，零 3D 引擎、零 GPU）
> 交付样本：《钢脊·白鸦》HX-07 概念片 v3 — 12.00s / 1280×720 / 24fps / 有声
> 评估日期：2026-11-06

---

## 1 结论（先行）

**这台机器上，纯代码程序化渲染能稳定做到「TV 动画赛璐璐着色 + 完整分镜 + 程序化配乐」的成片级水准，但天花板卡在「无贴图、无骨骼、无全局光照」三处。**

具体分三个层级说：

| 层级 | 能力 | 判据 |
|---|---|---|
| **A 级（已达成，可交付）** | 分镜叙事片、概念演示片、产品原理动画、数据流程动画 | 观众能看懂「这是什么、在干什么」；画面达到 B 站/抖音二次创作平均水平以上 |
| **B 级（可逼近，需加工作量）** | 游戏 CG 预告片质感、机甲番剧单镜头 | 需外挂法线贴图烘焙 + 骨骼插值，本管线要扩 2–3 倍代码量 |
| **C 级（做不到，必须换赛道）** | 电影级 CG、写实机械质感、人物面部表演 | 缺失：PBR、GI、景深、次表面散射、毛发/布料、动作捕捉 |

一句话：**它替代不了 Blender/UE，但它能把「从想法到有声成片」的周期从 2 周压到 2 小时，且完全跑在本地命令行里。**

## 3 能力边界

### 3.1 已经能做到

| 能力 | 实现方式 |
|---|---|
| **真实 3D 透视与视差** | 手写矩阵管线：世界→相机→透视投影→屏幕，五段机位含推轨/环绕/仰视 |
| **赛璐璐着色** | 漫反射量化到 5 个离散档位（0.42/0.60/0.78/0.94/1.0），加冷暖补光 + 逆光边缘 |
| **装甲分割线** | 每块甲片独立成件，靠每个多边形 0.60× 暗色描边勾勒，天然产生动画线稿感 |
| **涂装分区** | 6 级明度色板；白主色 / 蓝中段 / 红点缀 / 警示橙 / 深灰骨架 |
| **隐面消除** | 背面剔除 + 画家算法深度排序 + Sutherland–Hodgman 近平面裁剪 |
| **发光体 + Bloom** | 发光多边形单独渲到 glow 层，两级高斯模糊叠加 |
| **大气透视** | 指数雾（`1-e^(-a·d-b·d²)`），远楼自然压灰 |
| **运动关节动画** | 节点层级 + 每帧姿态插值（髋/膝/踝/肩/肘/腕 全 IK 式手动关键帧） |
| **HUD 叠加层** | 锁定框、标尺、装甲值、字幕、开机扫描线，含中文排版 |
| **程序化音效** | FFT 频域滤波 + ADSR 包络 + 扫频 + 棕噪声 + 延迟混响，12 秒完整配乐 0 素材 |
| **后期特效** | 速度线、光束轨迹、光剑挥砍弧、命中星芒、白闪 |
| **多格式输出** | 序列帧 / 单帧静帧 / 参数探针三模式 |

### 3.2 做不到（结构性缺失，非调参可解）

| 缺失能力 | 后果 | 补齐代价 |
|---|---|---|
| **纹理贴图（UV + 位图）** | 无法表现划痕、锈迹、编号喷字、迷彩、金属拉丝 | 需引入 UV 展开 + 纹理采样，渲染内核改写 |
| **PBR 材质** | 金属/塑料/橡胶读感一致，全靠纯色分区 | 需 BRDF + 环境贴图，工作量翻倍 |
| **骨骼蒙皮 + 关键帧动画** | 关节为刚性旋转，无法做肌肉挤压、装甲联动位移 | 需引入 skinning，且建模要从"盒拼"改为"连续网格" |
| **全局光照 / 软阴影** | 无相互反射、无接触阴影，暗部靠环境项硬抬 | 需光线追踪或 shadow map，CPU 纯 Python 不可行 |
| **景深 / 运动模糊** | 无镜头呼吸感，快速动作靠速度线补 | 景深可用多层高斯近似；运动模糊需多帧累积（渲染时间 ×N） |
| **曲面细分** | 圆柱为 7–10 边棱柱，近景可见棱面 | 提高 sides 即可，代价是多边形数与排序耗时线性增长 |
| **流体 / 粒子系统** | 烟雾、火花、爆炸为手绘星芒，无真实粒子 | 可写简单粒子，但 CPU 下帧率崩 |
| **人物 / 面部** | 完全不做人脸，本管线只适合机械与大场景 | 不补齐，直接用真人拍摄或外部资产 |

## 4 与「日日顺数据流程视频」的差异

那支片子（`flow3d/out/数据怎么变成动作_全片47s.mp4`，1920×1080 / 47s / 2148 kbps）与本片**不是同一类技术**，放在一起比较容易误判难度。

| 维度 | 日日顺数据流视频 | 本片《钢脊·白鸦》 |
|---|---|---|
| 技术栈 | HTML + CSS3D + Canvas，无头浏览器逐帧抓拍 → ffmpeg | 纯 numpy 3D 栅格化，无浏览器、无 GPU |
| 画面本质 | **2.5D 信息图**：节点卡片、箭头、数字滚动、图表 | **3D 实体几何**：有透视、有遮挡、有光照、有体积 |
| 单帧耗时 | 毫秒级（浏览器合成） | ~410 ms（纯 CPU 光栅化 1840 面 × 2× 超采样） |
| 修改成本 | 改 CSS/JS 即时预览 | 改参数重渲全片 2 分钟 |
| 适合内容 | 业务流程、数据链路、组织架构、产品原理 | 机械/产品外观、空间关系、动作演出、氛围片 |
| 不适合内容 | 任何需要"立体实物感"的镜头 | 任何需要"文字信息密度"的镜头 |

**判断原则**

- 要讲**逻辑关系**（A→B→C、数据如何流转、指标如何变化）→ 用日日顺那套 2.5D 信息图，成本低 10 倍、修改快 20 倍。
- 要讲**空间实体**（这台机器长什么样、怎么动、多大、什么质感）→ 用本片这套 3D 管线。
- 两者可以混剪：信息图层用 2.5D 出，产品/场景层用 3D 出，同一支片子里切换。

## 5 与真实 3D（UE5 / Blender）的差距

| 项目 | 本管线 | Blender EEVEE | UE5 Lumen |
|---|---|---|---|
| 画面观感（机甲题材） | 6 / 10 — 能看，风格化 | 8.5 / 10 | 9.5 / 10 |
| 建模精度 | 盒体拼接，1840 面 | 可 10 万面 + 细分 | 同左 + Nanite 亿级面 |
| 材质真实度 | 3 / 10 纯色分区 | 9 / 10 PBR | 10 / 10 |
| 动画能力 | 4 / 10 手动关键帧 | 9 / 10 骨骼+约束 | 9 / 10 + 动捕 |
| 单帧渲染 | 410 ms（CPU） | ~200 ms（GPU） | ~30 ms（GPU） |
| 上手成本 | 需写代码 | 需学软件 | 需学软件 + 硬件门槛 |
| 可自动化 | **10 / 10 纯命令行、可脚本化** | 6 / 10 Python API | 5 / 10 |
| 可复现 | **10 / 10 代码即资产** | 5 / 10 二进制工程文件 | 4 / 10 |

**核心差异不在画质，在"产能模型"**：

- UE5/Blender 是**美术驱动**——一个镜头 1–3 天，靠人打磨。
- 本管线是**代码驱动**——一个镜头 30 分钟，改一行参数重渲。同一套代码可以批量产出 50 个不同机体、不同机位的镜头。

所以它的正确定位不是"低配版 UE"，而是**"参数化视频工厂"**：适合需要大量变体、需要频繁改数、需要嵌进自动化流程的场景。

## 6 成本与迭代周期（实测）

| 环节 | 本次耗时 | 说明 |
|---|---|---|
| 渲染内核（首次） | ~3 h | 矩阵/投影/裁剪/着色/雾/Bloom，一次性投入，后续复用 |
| 机体建模（首次） | ~4 h | 1610→1840 面，含 6 级色板、装甲分块、关节层级 |
| 分镜与运镜 | ~1.5 h | 5 段机位 + 姿态时间轴 + 构图反复调 |
| HUD 与字幕 | ~1 h | 含中文排版 |
| 程序化配乐 | ~1.5 h | 12 秒全合成 |
| **二次迭代（改涂装/改机位）** | **~25 min** | 改参数 → 重渲 2 min → 编码 20 s → 质检 2 min |
| 全片重渲 | 121 s | 288 帧，单核 |
| 编码 | ~20 s | libx264 CRF17 preset slow |

**关键结论：边际成本极低。** 第一个镜头 12 小时，第十个镜头 25 分钟。这套代码已经是资产，不是一次性工程。

## 7 必须外包补齐的部分

对齐《建模外包内容清单》A1–A3 的 P0 分件，以下**建议外包精模**，不要用程序化几何硬撑：

| 优先级 | 内容 | 理由 |
|---|---|---|
| **P0** | 头部与胸舱特写（A1/A2） | 特写镜头下棱柱边长与无贴图问题会被放大到无法接受；这是"序章仰视"的主体，占全片视觉权重最高 |
| **P0** | 涂装贴图（编号、队徽、警示带、磨损） | 纯色分区无法表达"用过"的质感；一张 4K 贴图能顶 500 行代码 |
| **P1** | 手部与武器（A4/A5） | 手指分段为盒体，握持姿态僵硬；射击/持剑镜头会穿帮 |
| **P1** | 关节联动结构（A6） | 刚性旋转导致裙甲/肩甲在极限姿态下穿模 |
| **P2** | 背景城市 | 当前为压缩楼体，只在中远景成立；近景需替换 |

**外包交付规格建议**：FBX/GLB，单机体 ≤ 8 万面，贴图 4K PBR（BaseColor / Roughness / Metallic / Normal），骨骼绑定 + 一个 Idle 动画循环。这样接手后本管线只需替换几何数据源，渲染与分镜层可保留。

## 8 技术栈与复用方式

```
mecha_render/
├── r3d.py           466 行  渲染内核（矩阵/图元/着色/雾/Bloom/裁剪）
├── mecha_model.py   444 行  机体建模（色板/分件/层级/姿态参数）
├── film2.py         399 行  分镜（运镜/姿态时间轴/后期特效/字幕）
├── hud.py           180 行  HUD 叠加层
├── audio.py         237 行  程序化配乐合成
├── diag.py                  ASCII 预览 + 数值诊断（无显卡环境的自检）
├── crop_diag.py             主体裁剪放大诊断
├── sheet.py                 关键帧拼图
└── out/
    ├── steel_spine_v3.mp4   成片
    ├── sheet_v3.jpg         12 关键帧拼图
    └── score.wav            配乐音轨
```

**换题材只需改 `mecha_model.py`**：把 `build_mecha()` 换成 `build_product()` / `build_factory()` / `build_wind_turbine()`，渲染内核、分镜、HUD、音频全部复用。

**命令行接口**

```bash
python3 film2.py still 8.3          # 单帧静帧（调试构图）
python3 film2.py probe 0.5 6.0 11.5 # 投影包围盒探针（校验构图占比）
python3 film2.py seq 1280 720       # 全片序列帧
```

**编码（本机完整版 ffmpeg 8.1.2）**

```bash
FF="/Users/zhukeyi/Library/Application Support/TRAE SOLO CN/ModularData/ai-agent/vm/tools/opt/ffmpeg/8.1.2/bin/ffmpeg"
"$FF" -framerate 24 -i frames/f_%04d.png -i out/score.wav \
  -vf "scale=in_range=full:out_range=tv:out_color_matrix=bt709" \
  -c:v libx264 -crf 17 -preset slow -tune animation -pix_fmt yuv420p \
  -colorspace bt709 -color_primaries bt709 -color_trc bt709 -color_range tv \
  -c:a aac -b:a 192k -shortest out.mp4
```

> **色彩元数据必须显式写**：PNG 是全范围（pc），H.264 默认按 tv 解释，不显式声明会导致播放器里整体发灰。`-pix_fmt yuv420p` 单独写不够。

## 9 编码器选型（回答先前提问）

**ffmpeg 不是编码器，是封装工具链**——真正的编码器是它调用的 `libx264` / `libx265` / `prores`。

| 用途 | 推荐 | 理由 |
|---|---|---|
| **最终成片（H.264）** | `libx264 -crf 17 -preset slow -tune animation` | `-tune animation` 专为平涂色块优化，保护赛璐璐锐边不被过度平滑 |
| **快速预览迭代** | `libx264 -crf 23 -preset ultrafast` | 20 秒出片，够看构图 |
| **中间片 / 二次调色** | `prores_aw -profile:v 3`（ProRes 422 HQ） | 全帧内，10bit，反复编解码不掉画质 |
| **更小体积** | `libx265 -crf 20 -preset slow` | 同画质体积约 −40%，但兼容性差一些 |
| **硬件加速（M 系芯片）** | `h264_videotoolbox -q:v 65` | 快 5–8 倍，但色块边缘质量明显不如 libx264，只适合预览 |

**本片选择 libx264 CRF 17 + tune animation**：赛璐璐画面是大量纯色平涂 + 硬边，这个组合能在 3.7 MB 内保住所有装甲分割线不发虚。
