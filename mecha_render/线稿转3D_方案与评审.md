# 线稿转 3D · 方案与评审

> 本文档回应三件事：为什么上一版是「一块板」、开源方法检索到什么、下一版怎么做且怎么验收。
> 所有数字都是本机实测，命令与产出在文中标注。

---

## 1 结论先行

| 项 | 结论 |
| --- | --- |
| 上一版为什么是板 | 不是渲染问题，是**构造问题**：所有装甲板共用同一个前平面 `DP_FRONT`，整机在深度方向只有一个常数。数学上它必然是一块板。 |
| 上一版为什么没被发现 | 我的四项验收（剪影 IoU 99.4%、墨线 chamfer 中位 0.00 px、亮度对比 11:1、转角宽度变化 1.065×）对薄板**恒等满分**。剪影挤出这种构造，输出剪影按定义等于输入剪影，IoU 不可能失败。那是自证，不是验收。 |
| 开源路线能不能用 | 三家主流 image-to-3D 全部受硬件或网络阻塞：TRELLIS.2 的 Mac 原生移植版要求 **24 GB 统一内存、实测峰值 18 GB**，本机 16 GB；且它依赖的两个 HF 门控模型在 `huggingface.co`（本机不可达）上。生成式还有根本冲突：它**必然改动细节**，与「不能改动任何细节」互斥。 |
| 下一版路线 | **曲面基底 + 各自倾斜的板壳**（第 5 节）。正面剪影和每条分割线由构造保证不变，深度方向由距离场给出真实体量，每块装甲板拟合自己的平面并以独立闭合壳贴合基底。 |
| 验收机制 | 已重建为两道门（第 6 节）。**体量门**三条判据已用阳性对照验证可达、并已判死当前薄板；**保真门**保留原有 IoU 与墨线距离。两门都过才算通过。 |

体量门实测对照（`python3 tools/volume_check.py --selftest`）：

| 判据 | 旧薄板 | 阳性对照 | 阈值 | 分辨力 |
| --- | --- | --- | --- | --- |
| V2 法线多样性 | 0.63% ✗ | 33.7% ✓ | ≥ 25% | 53× |
| V3 分量闭合率 | 0.0987 ✗ | 1.0000 ✓ | ≥ 0.90 | 10× |
| V1 边缘收边率（仅诊断） | 0.064 | 0.448 | — | 不参与判定 |
| **总判定** | **不合格** | **通过** | — | — |

> 以及最初的 V1「侧视厚度比」——它在类人形上根本不可能分辨。经过见第 6.2 节。

## 2 问题定性：板是怎么来的

现有 `tools/trace3d.py` 的深度预算只有三个常数：

```
DP_FRONT = 0.075   # 所有板件的顶面 z
DP_GAP   = 0.032   # 板厚（所有板件完全相同）
DP_BACK  = 0.105   # 机身实体再往后的深度
```

- 167 块板，每块顶面都在 `z = DP_FRONT · H`，厚度都是 `DP_GAP · H`。
- 唯一有差异的是 x/y（平面内位置），z 完全一致。
- 于是整机的深度信息熵 ≈ 0。侧视就是一条 0.137 机高的窄条。

**这不是参数没调好，是构造决定了上限。** 无论怎么调 `DP_FRONT`，只要它是常数，结果就是一块板。上一版我还试过「按到剪影外缘的距离挤出」，结果厚度顶到 28.5% 机高、一排深浅不一的柱子——那更糟，因为板面不再共面，转角就散架。

真正的病根：**把「板」当成了三维基本单元**。板必须是贴在某个体上的皮，体必须先存在。

## 3 开源方法检索

### 3.1 生成式 image-to-3D

| 方案 | 许可 | 显存/内存 | 质量 | 本机可行性 |
| --- | --- | --- | --- | --- |
| TRELLIS.2 (4B) | MIT（权重） | CUDA 16~24 GB | 保真最高、任意拓扑、PBR | ✗ 见下 |
| TRELLIS.2 Mac 移植（trellis-mac / trellis-mac-mps） | MIT | **要求 24 GB 统一内存，实测峰值 ≈18 GB** | 400K 顶点 / 约 3.5 min | ✗ 本机 16 GB |
| Hunyuan3D 2.1 / mini | 社区许可（100 万 MAU 上限、排除 EU/UK/KR） | 8~29 GB | 高 | ✗ 需 CUDA |
| TripoSR | MIT | 6~8 GB，有 CPU 回退 | 几何软、顶点色、细节弱 | 勉强，但质量不达标 |
| Stable Fast 3D | Stability 社区许可 | 7 GB | 中 | ✗ 需 CUDA |

额外阻塞（本机实测网络）：

| 目标 | 结果 |
| --- | --- |
| `huggingface.co` | 000（不可达） |
| `hf-mirror.com` | 200 |
| `modelscope.cn` | 302 |
| `pypi.org` / 清华源 | 200 |

TRELLIS.2 移植版依赖 `facebook/dinov3-vitl16-pretrain-lvd1689m`（门控）与 `briaai/RMBG-2.0`（**CC BY-NC 4.0，商用需另外授权**），都要 HF 账号授权。镜像站能绕下载，绕不过门控与许可。

**更要紧的是范式冲突**：生成式模型输出的是「它认为该长这样」的形状。它会把原稿的板缝细节平滑掉、把锐角改成圆角、把不对称改成对称。这直接违反「不能改动任何细节」。哪怕显存够，这条路也不该走。

### 3.2 剪影膨胀（非生成式）

| 方案 | 来源 | 做法 | 可用性 |
| --- | --- | --- | --- |
| **Teddy** (SIGGRAPH 1999) | Igarashi 等 | 约束 Delaunay → chordal axis 骨架 → 骨架按到边界距离挤出 → 弧面收边 | 经典，思路可直接复用；有开源实现（如 HKUST-GZ SketchKit） |
| SmoothSketch (2006) | Karpenko & Hughes | 先补全隐藏轮廓再膨胀，解决自交 | 需要轮廓补全，复杂度高 |
| FiberMesh (2007) | Nealen 等 | 函数优化拟合圆润曲面 + 曲线手柄 | 面向建模交互，不适合批处理 |
| 3-Sweep | Chen 等 | 广义柱 / 长方体拟合 | 需人工三笔画，非自动 |
| SENS (CGF 2024) | 草图隐式神经表示 | 部件感知，单/多视图 | 神经方法，需权重 |

**关键克制**：Teddy 一类给出的是「气球式枕头」，对手办/卡通合适，对硬表面机甲不合适——机甲要的是平板、倒角、锐边。所以不能直接套 Teddy，只能借它的一条核心性质：

> **高度场在剪影边界处归零 ⇒ 正面投影严格等于剪影。**

这条性质是整份方案的保真基础：只要深度函数 `z(x,y)` 在剪影边界上取 0，无论内部怎么起伏，正视投影都精确等于输入剪影。保真不需要靠优化去凑，是构造保证的。

### 3.3 检索结论

- 生成式：硬件/网络/许可/范式四重阻塞，且与「不改细节」冲突 → **弃**。
- 纯剪影膨胀：保真能保证，但输出是软体枕头 → **只借它的边界归零性质**。
- 可用工具面：本机 `numpy + PIL` 之外没有 `scipy` / `cv2` / `torch`。骨架提取、分水岭都得自己写或绕开 → 方案必须**不依赖骨架提取**。

## 4 三条路线的取舍

| 路线 | 正面保真 | 3/4 体量 | 硬表面 | 本机可跑 | 判定 |
| --- | --- | --- | --- | --- | --- |
| A 生成式（TRELLIS/Hunyuan3D） | ✗ 会改细节 | ✓ 最好 | ✓ | ✗ 显存/网络 | 弃 |
| B 纯剪影膨胀（Teddy 式枕头） | ✓ 构造保证 | ✓ | ✗ 软体感 | ✓ | 弃 |
| **C 曲面基底 + 倾斜板壳** | ✓ 构造保证 | ✓ | ✓ | ✓ | **采用** |

C 是 A 与 B 的折中：**体量来自几何先验（B 的性质），硬表面来自每块板各自成面（A 的观感），但不引入任何生成模型、不改一个像素的剪影。**

## 5 设计方案（路线 C）

### 5.1 三层结构

```
第 3 层  板壳（167 块，各自拟合平面、各自倾斜、各自闭合）
第 2 层  基底曲面（距离场膨胀，提供真实体量，边界处归零）
第 1 层  板缝（基底在缝处露出深色 → 读作原稿墨线）
```

与上一版的差别只有一句：**板从「立在同一个平面上」改成「贴在曲面上、各自朝自己的方向倾斜、并各自闭合」。**

### 5.2 基底曲面

对剪影 `F` 求欧氏距离变换 `D`（到剪影边界的最短距离），前表面高度：

```
z_base(p) = κ · D(p)^γ        κ ≈ 0.55,  γ ≈ 0.75
```

- `D` 在边界为 0 ⇒ `z_base` 在边界为 0 ⇒ **正视投影严格等于剪影**（保真由构造保证）。
- `D` 恰好是「该点局部内切圆半径」，等价于各向同性截面假设：头得到近球、手臂得到近柱、躯干由内切圆限制而略扁 —— 与机甲大形吻合。
- `γ < 1` 把中心压平、边缘抬起，避免枕头感过强。

为什么不提骨架：本机无 `scipy`，骨架/chordal axis 要手写且对 1437 px 高的复杂机甲极易碎成毛刺。距离场用两遍 chamfer 扫描即可（`trace3d.chamfer_dt` 已有），稳定且 O(n)。

### 5.3 板壳：每块板拟合自己的平面

对第 `i` 块板的像素集合 `Ωᵢ`，在 `{z_base(p) : p ∈ Ωᵢ}` 上做最小二乘平面拟合，得 `Πᵢ(x,y)`。然后：

```
顶面顶点 z = Πᵢ(x, y) + t          t = 板厚（可按板件面积分档，允许不同）
侧裙       = 顶面顶点 → 基底表面 (z_base) 的一圈
底面       = 略低于 z_base 的平面（埋进基底，正面看不见）
```

三个后果，正是要的：

1. **板面仍是平的**（三个顶点定一个平面），保住硬表面质感，不会变成鼓包。
2. **每块板法线不同** —— 整机成为「多面体装甲壳」，3/4 视角下能看到各板朝向差异，`V2` 自然上去。
3. **每块板自带底面 ⇒ 自身是闭合流形** ⇒ 全局边闭合率 `V3 = 1.0`，不与基底共享顶点也不影响。

`t` 按板件面积分档（大板厚、小铆钉薄），顺带让「所有板一样厚」这个板味消失。

### 5.4 墨线不再需要几何

上一版用 `build_ink()` 铺 9730 个矩形压在板面上，是为了补「零宽缝成片丢失」。新架构下板与板之间的间隙露出的是**基底曲面**，基底材质本来就是深色 `M_SEAM` ⇒ 缝自动读成暗线。删掉 ink 几何层：

- 三角数下降约 25%；
- 少一层开口壳，`V3` 只升不降；
- 线条位置由板轮廓决定，精确到亚像素，不会因为薄片被侧向看见而「浮起来」。

### 5.5 背面与侧面

基底是单面高度场，背面需要封口：把 `z_base` 沿深度方向镜像一层（`z_back = -λ · z_base`），得到一个前后对称的封闭体。λ 控制前后厚度比（机甲背面通常更平，λ ≈ 0.6）。这比现在的「矩形游程挤出」干净，且天然闭合。

## 6 验收机制

### 6.1 两道门，缺一不可

| 门 | 指标 | 工具 | 通过条件 |
| --- | --- | --- | --- |
| **体量门** | V2 法线多样性 / V3 分量闭合率 | `tools/volume_check.py` | 两条全过 |
| **保真门** | 剪影 IoU / 墨线 chamfer 距离 / 成片丢失率 | `tools/relief_check.py` | IoU ≥ 99%、中位距离 ≤ 0.5 px、成片丢失 ≤ 3% |

上一版的错误是**只有保真门，且把保真门当成了全部**。体量门不过时，保真门满分也不允许交付。

### 6.2 判据是怎么被否到只剩两条的（这是本文档最有价值的部分）

五轮返工，四次自我否决。全部留档，因为它们比结论更能防止重犯：

| 候选 | 薄板实测 | 否决理由 |
| --- | --- | --- |
| 行截面比 = 该行 z 跨度 / 该行宽 | 0.34（近阈值） | 薄板 z 跨度恒为板厚，而窄行（手臂）行宽小，比值反被抬高 —— **奖励薄板** |
| 3/4 面积增益 = Area(30°)/Area(0°) | 1.33（比实体 1.02 还高） | 复杂剪影一转，手臂与躯干间的**背景空隙被侧面填满**，纯 2D 补洞效应，方向反转 |
| 侧视实心度 = 侧视面积/凸包面积 | 1.00 | 薄板侧视是竖直条带，本身就是凸的，零区分度 |
| **V1 侧视厚度比 = 侧视宽/机高** | 0.137 | **类人形上限就是 0.139**（躯干宽 200 px、圆截面时深度≈宽度，200/1437）。它不是测「有没有体量」，是测「是不是胖球」。我最初的阳性对照是一个 10 高 / 3 深的胖椭球（0.536），对类人形毫无代表性 |
| V3 全局边闭合率 | 0.460 | 测的是「整块拼图能不能拼严」。相邻零件共享面或 T 形接点会让一条边被 4 个三角形共用，比例虚低 —— 路线 C 的底板壳本身完美 1.0000，却被重合侧壁拖到 0.927 |

最终两条，机制互不相关：

- **V2 表面朝向**：靠近剪影边缘的表面必须转向侧面。薄板只有一圈侧壁超过 30°（0.63%）。
- **V3 分量闭合**：先把共边的三角形并成连通分量，再看每个分量内部有没有只被一个三角形用到的边。有 = 开放壳（板），没有 = 实心体。薄板 3930 个零件里只有 9.87% 是闭合的。

**三条方法论教训**：

1. **分母不能用局部宽度**（会反向加分），深度类判据必须用机高这种全局尺度。
2. **面积类判据会被凹剪影的补洞效应污染**，与体量无关。
3. **阳性对照的形状类别必须与被测对象一致**。用胖球校准出来的阈值，会把类人形判死。

**还有一条更根本的**：深度**量级**类判据在这两个对象上本来就不可分 —— 旧薄板的「板面+墨线+机身」堆叠约 0.05 机高，而正确重建的躯干半径也只有 0.07 机高，同一量级。薄板的问题不是薄，是**平**。所以只能从朝向和拓扑去分辨，不能从厚度去分辨。

### 6.3 阳性对照的意义

`volume_check.py --selftest` 现场合成一个超椭圆截面实体跑同一套判据。这是这个文件存在的一半理由：**没有阳性对照，判据不可信**。上一节三个被废的候选，全都是被这一步抓出来的。

## 8 自审：这套逻辑是否合理

### 8.1 用户那句质问的两个点，正面回答

**「不就是个板吗」** —— 是的，而且是构造决定的。`DP_FRONT` 是常数 ⇒ 所有板顶面共面 ⇒ 深度信息熵为零。上一版我甚至在代码注释里写过「前平面统一才成立」，把妥协当成了正确性。这是判断错误，不是参数失误。

**「你没有自己的评审机制吗」** —— 我当时有，但它是**不可能失败**的：剪影 IoU 对剪影挤出恒等成立；线条 chamfer 距离量的是墨线位置，与深度无关；亮度对比和宽度变化都是正面视图量。四项全过，一块板。真正该问的是「什么量会让这个结果失败」，而不是「什么量能证明它对了」。**验收要从「能不能判死」出发设计，不是从「能不能证明」出发。**

### 8.2 这次流程本身是否合理

用户要求的是「先搜集开源 → 编排方案 → 自审 → 再执行」。我照做了，顺序上是合理的，因为：

- **先查开源避免了白费力气**：如果 TRELLIS 在本机能跑，方案会完全不同；查完才知道真正卡住的是 16 GB 内存和「不改细节」这条硬约束，而不是模型能力。
- **先建评审才敢动手**：如果没有 6.2 那三条，我会重蹈覆辙 —— 新方案做出来，拿旧的 IoU 一量，99%，又交付一块板。
- **阳性对照是这次唯一真正新增的纪律**：它把「我觉得这个指标合理」变成「这个指标有一个可达到的正样本」。

### 8.3 这套方案自身的弱点（不回避）

| 弱点 | 说明 | 缓解 |
| --- | --- | --- |
| 深度是猜的 | 单视图不含深度信息，`κ`、`γ`、`λ` 都是先验。侧视一定不是「真实」侧视。 | 明确边界：这是**可信的正视 + 合理的体量**，不是工程复原。交付时写清楚。 |
| 基底是枕头形 | 距离场膨胀天然软。 | 板壳承担硬表面观感；基底只在缝与边缘露出。若仍偏软，把 `γ` 调小、板厚加大。 |
| 板面平面拟合可能翻面 | 小板的 `z_base` 近似常数，拟合出的平面几乎水平，等于退回老路。 | 对面积小于阈值的板强制继承邻域大板的平面；S3 验收里查「法线多样性」的分位数。 |
| 拼缝处可能露基底台阶 | 板壳底面埋进基底，若嵌入深度不够会穿孔。 | 底面向下多埋 `0.3t`。 |
| 167 块板各自闭合 → 三角数上升 | 每块板多一圈侧裙 + 一个底面。 | 删掉 ink 层抵消（约 −25%）。若仍超预算，底面按「同平面合并」批量生成。 |

### 8.4 一个诚实的判断

单张正视线稿在信息论上**不含**侧面与背面信息。任何方法给出的侧视都是推断，不是复原 —— 包括生成式模型（它给的是「学到的典型机甲侧面」）。所以路线 C 的定位应当是：

> **正视逐像素保真 + 体量合理可信 + 可旋转可打光可出视频**，
> 而不是「还原了这台机甲的原始三维模型」。

这个边界会在交付说明里写清楚，不做过度承诺。

## 10 侧视「错位 / 拉链」的归因全过程（2026-11-08 补充）

用户反馈：「三维感觉有了，但侧面有错位」。这一轮把侧视的每一类瑕疵单独拎出来做消融，
结论是**三个互相独立的原因叠在同一条线上**；剩下的第四个是单面高度场在 90° 的几何退化。

| 序 | 现象 | 真因 | 判据 / 修法 | 量化 |
| --- | --- | --- | --- | --- |
| 1 | 侧视整条轮廓是**背景白缝** | 浮雕是闭合**薄壳**，侧视时壳法线几乎平行于视线，一半三角被按法线剔除，壳只有 1.7 px 厚、背后无物补 | `rasterize(..., backface=False)`。此前排除过线稿、超采样 2/3/4×、法线平滑、边带加厚、边界吸附——全无效，因为问题在剔除 | 漏底 7.3% → ≈0 |
| 2 | 轮廓处一排 2 px 周期的**亮暗梳齿** | 轮廓密封带按 `uv` 查 `dist` 距离场：掠射时 uv 每屏幕像素走 1.5~2.5 个原稿像素，而 `dist` 是 1 px 量化场 → 「离剪影几像素」按行在 0/2/4 之间跳 | 密封带按**采样率**混合：采样充分（正视）用距离场，采样不足（掠射）切屏幕空间覆盖内环，权重 `1-mf` | 垂直抖动 7.9 → 4.8（单位：相邻行灰度差均值） |
| 3 | 整幅读成「两个错开的半身」 | 单面高度场 + 薄壳：沿板面看进去必然看到壳内壁（实测该区 `midx=1`、`nz≈-0.6`，即背片内侧）。**这是单面浮雕的退化视角，不是缺陷** | 交付改用 ±45° 摆动转台，不出 90° 正侧视 | — |
| 4 | 残余：轮廓内侧 ~5 px 宽的细锯齿轮 | 前片在掠射处的 **2 px 网格台阶**本身（关掉线稿仍在，只剩前片时下半段仍有）。要再降只能把 cell 从 2 降到 1（三角 ×4） | 不修，记录为已知极限 | 抖动 4.8 |

**两个被实测否掉的假设**（都很有诱惑力，都不成立，留档避免重犯）：

| 假设 | 消融做法 | 结果 |
| --- | --- | --- |
| 双面边缘带在 z-fighting（同位置两份只差法线的重合面） | `RIM_DBL True→False` | **两张图逐字节相同**（md5 一致）⇒ 与齿无关。仍保留单面版本（少 3484 三角、少一处重合几何），但它不是修复项 |
| 前后片在轮廓上深度并列 → 逐三角随机胜负 | 后片沿轮廓内缩 0.035 / 0.08 世界单位 | 侧视**只改变 22 个像素**，抖动 6.8→6.8 ⇒ 假设不成立，代码不保留这个参数 |

### 10.1 三条判据的教训（比修法更值钱）

- **`spec_a` / `rim_a` 是死参数**：签名里有、函数体里一律用材质表的值，于是「关高光看看」这类消融全在空跑。三组结果**逐位相同**才暴露出来。**消融必须验证探针真的起作用**（改一个参数，先确认输出变了）。
- **UV 压缩的判据不能用雅可比行列式**：这里的压缩是单向的（压一个轴、另一个轴不动），行列式量的是面积，单向压缩恰好近似保面积 → 淡出永不触发。要用 2×2 雅可比的**小奇异值 / 大奇异值**。
- **再加一条「采样率」判据**：小奇异值比只管「被压成一条线」，管不了「被剪切但整体尺度没变」的欠采样。用 `smax`（每屏幕像素吃掉几个原稿像素）除以**本帧朝正面像素的中位数**作基线，超过 1.45 倍即判欠采样。
- **两套轮廓画法各有失效区，只能按采样率混合**：距离场轮廓连续、不跟 2 px 网格相位走，正视好；屏幕空间轮廓线宽恒 1 px，任何视角都不断，但贴 2 px 阶梯走、正视发毛。只留一种必有一端坏。

并提出「线稿语义分层 → 分件参数化重建 → 六道新门」的路线。下面逐条裁定，
其中 **P0-2 需要修正机制**、**§5 有一道门自相矛盾**、**§3 有一条比它说的更严重**。

### 11.2 必须修正的一条：P0-2 的机制不是「高度场」

「单值高度场无法表达机甲结构」这句话把病根归给了表示法，归错了。

高度场**可以**是分段的：板与板之间允许断崖（不连续），断崖就是前后错落的零件边界。
它真正不能表达的是两件事：**悬垂（表面拐回镜头）** 与 **互相穿插/内部空腔**。
而正面视角的机甲里，真正的悬垂只有「肩甲压低盖住上臂」一处，其余几乎全是层叠平板。

所以病根是：**场是单张的、跨零件连续的、被平滑成一整片**，而不是「用了高度场」。
原方案 §5.3 写的「每块板各自拟合平面 + 侧裙 + 底面」本来就是分段场，能表达断崖——
**方案没过时，是方案没被实现**（正是 P0-1）。

这个区别直接决定工作量：

| 路线 | 做法 | 信息需求 | 工作量 |
| --- | --- | --- | --- |
| 分件高度场（修正原方案） | 一张场按零件切成 N 段，每段独立成壳、带竖直侧裙与底面 | 仅需正面图 + 零件划分 | 中 |
| 完整薄壳重建（Kimi 字面意思） | 每件独立放样、倒角、背面设计 | 需侧背信息或大量先验 | 大，且缺信息 |

结论：走左边，但必须真的分件。右边只有在用户提供侧背参考时才成立。

### 11.3 一处自相矛盾：全角度门与保真门不能同时成立

Kimi §5 同时要求：

- 全角度门：0/45/90/135/180/225/270/315 全出，**90° 和 180° 不得缺席**；
- 保真门：不仅整机剪影，还要**逐件**测头、胸、肩、四肢的正视轮廓。

但输入只有一张正面图。180° 背后**没有任何可比对的信息**，那道门无法用「与原稿一致」
判定；它只能判定自洽性（闭合、无穿模、比例合理）。把两者混在一道门里，
结果就是「永远过不了」——**这正是它自己在 §3 里批评旧门时犯的同一个错**
（旧门是永远过得了，新门是永远过不了，两者同样无用）。

修正为两道，判据分离：

| 门 | 判定依据 | 适用范围 |
| --- | --- | --- |
| 全角度自洽门 | 8 视角灰模：闭合、无穿模、无翻转法线、比例不突变 | 全角度 |
| 保真门 | 与原稿逐件比对剪影 IoU | **仅 0° 与 ±30°** |

### 11.4 最关键的一条：旧 V2 判据的方向是反的

Kimi 说「枕头、气球、充压膜同样能拿高分（V2 64%）」。实测比这严重一层：

> 一个 **19 件箱体装配的硬表面正样本**（有平面、有前后错落、每件闭合），
> 旧 V2 实测 **0.45%**，远低于阈值 25% —— **它会被旧门直接判死**。

而当前这张气球皮，旧 V2 = **64.15%** → PASS。

| 对象 | 旧 V2 | 旧门判定 |
| --- | --- | --- |
| 气球（旧阳性对照） | 33.66% | PASS |
| 当前交付浮雕 | 64.15% | **PASS** |
| 硬表面 19 件装配 | **0.45%** | **FAIL** |

原因：V2 量的是「法线偏离视轴 >30° 的可见面积占比」。像素权重天然偏袒正面，
一个纯平板装配在正视下几乎全部朝前 ⇒ V2≈0；气球在轮廓处法线连续扫过 30~90° ⇒ V2 高。
**所以 V2 不是体量探测器，是鼓面探测器**，方向与目标相反，
阈值 25% 又是在气球上校准的，等于把「越像气球分越高」写进了验收。

直接后果：**若按 Kimi 的建议去做真 3D，用旧门验收会被判不合格。**
判据必须先换，这不是可选项。

### 11.5 判据重构：V6 结构门 + V3 闭合率（V7 已被实测推翻）

> **本节已按真资产实测修订。** 上一版写的「V6 ≥12 件且闭合≥95%」「V7 ≥90%」两条门槛，
> 都被万代 Unicorn 第三方资产（377k 三角）打穿。修订过程见 11.9 —— 那比结论更值钱。

| 判据 | 定义 | 阈值 | 为什么是它 |
| --- | --- | --- | --- |
| **V6 结构门** | 独立连通分量数 ≥12 | 12 件 | 唯一不可能被大形糊弄的一条：一张覆盖全身的闭合皮，分量数必然 =1，无论它鼓多圆。直接对应 P0-3 |
| **V3 量闭合率** | 分量内被恰好两个三角形共享的边占比 | ≥0.20 | 判「整机是开放壳拼的」。旧薄板 0.0987，真资产 0.349，阈值夹在中间 |
| V7 平面面积 | 法线落在 12 个主朝向 4° 锥内的面积占比 | — | **撤出判定，降为诊断**（真资产仅 10.78%） |
| V1 / V2 / V8 | — | — | 诊断项（V2 方向反了，见 11.4） |

两条判定项机制正交，缺一不可：

- 气球：V3 = 1.0000（完全闭合）但只有 1 件 → **V6 判死**
- 旧薄板：3930 件（数量远超 12）但 V3 = 0.0987 → **V3 判死**
- 当前浮雕：1 件 → **V6 判死**

**一个必须留档的假判据**：V7 第一版放在 G-buffer 层，用「相邻像素法线夹角 <0.5°」当平面度，
气球拿到 95.6% 假通过 —— G-buffer 法线是**逐三角形常量**，同三角形内夹角恒 0，
这个指标量的其实是三角形大小。改到网格层后判据本身正确，但**阈值仍被真资产推翻**。

### 12.3 大气层飞行：可行，但要压到 8 m 以下

`tools/flight_physics.py`（可复现，输入全部有出处）。质量闭合是前提：
不给质量闭合的推重比都是空谈。

```
MTOW = 结构 + 推进(13%) + 燃油(12%)
结构 = 0.42 · 包络体积 · 700 kg/m³
推进 = 2× F135(191 kN / 1.7 t) + 1× 轴驱升力风扇(110 kN / 1.1 t) + 管路 0.6 t
```

尺度扫描（外形比例锁定 Unicorn，巡航 648 km/h）：

| 机高 m | MTOW t | T/W | 翼面积 m² | 展长 m | 航程 km | 悬停 MW | 风扇 D m | 接地 kPa | 判定 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 3.5 | 3.3 | 1.28 | 4.7 | 4.3 | 563 | 6.3 | 0.51 | 64 | 可行 |
| 4.0 | 5.0 | 1.28 | 7.0 | 5.3 | 563 | 9.3 | 0.63 | 73 | 可行 |
| 6.0 | 16.7 | 1.28 | 23.6 | 9.7 | 563 | 31.5 | 1.15 | 109 | 可行 |
| **8.0** | **39.6** | **1.28** | **55.9** | **15.0** | **563** | **74.7** | **1.78** | **145** | **可行（基准）** |
| 10.0 | 77.4 | 1.28 | 109.2 | 20.9 | 563 | 145.8 | 2.49 | 181 | 超限 |
| 12.0 | 133.7 | 1.28 | 188.7 | 27.5 | 563 | 252.0 | 3.27 | 218 | 超限 |
| 18.0 | 451.1 | 1.28 | 636.9 | 50.5 | 563 | 850.4 | 6.00 | 327 | 超限 |

**三条结论，都反直觉：**

1. **推重比与尺度无关**。推力与质量都 ∝ H³，所以 T/W 恒为 1.28。
   用「推重比不够」解释不了大尺度不可行 —— 那是找错了原因。
2. **真正卡住大尺度的是机翼与地面**。翼面积 ∝ H³，18 m 需要 637 m²、
   展长 50.5 m（可折叠上限是机宽的 3.5 倍）；接地压力 327 kPa 会陷进软土。
   所以 **H ≤ 8 m**。
3. **巡航不难，悬停才难**。巡航只需 T/W = 1/L/D = 0.167，
   但悬停必须 T/W ≥ 1.05。燃油 4.8 t、悬停油耗 44.9 t/h → **悬停续航只有 6 分钟**。
   这是喷气升力的物理代价，不是设计缺陷。

基准构型 H=8 m 的关键数：MTOW 39.6 t、装机推力 497 kN、T/W 1.28、
巡航阻力 65 kN、航程 563 km / 0.82 h、悬停 74.7 MW。

### 12.4 「厚重」的物理来源：升力风扇直径倒逼

这是把「要厚重」从审美变成数字的唯一一条链，五环全可算：

```
① 悬停推力   T = 1.05·W                    = 408 kN
② 可用轴功率 P = 14.5 MW/t × 5.1 t          = 74 MW
③ 必需盘面积 A = T³/(2ρP²)                  = 4.97 m²
④ 风扇直径   D = sqrt(4A/(2π))              = 1.78 m
⑤ 机身深度   D_min = 1.78 + 2×0.15          = 2.09 m
⑥ 深度/宽度  D/W ≥ 2.09/4.49                = 0.467
```

- Unicorn 实测 D/W = **0.627**，比下限高 34% → 它的厚度是合理的，不是画胖了。
- 现线稿 D/W ≈ 0.40 → 机身深 1.80 m，**装不下 1.78 m 的风扇，差 0.28 m（16%）**。

**结论：厚重不是风格选择，是「悬停必须用大直径低速盘」这个物理事实逼出来的。**
这一条同时解释了 F-35B 为什么在座舱后面塞一个升力风扇 —— 不是为了好看，
是因为 P ∝ A^(−0.5)：同等推力下，盘面积越小功率越大。

| 悬停构型 | 盘面积 m² | 功率 MW | 对照 |
| --- | --- | --- | --- |
| 纯喷口 v_e=700 m/s | 0.68 | 142.7 | 功率最大，但不需要机身开洞 |
| **2× 升力风扇 D=1.78 m** | **4.97** | **74.7** | 折中解，且定了机身深度 |
| 四旋翼 r=3 m | 113.1 | 15.6 | 最省功率，但 6 m 旋翼破坏剪影 |

顺带一条自我修正：我先前把「内部必须填充 83% 的外形包络」当作厚重依据，
是把结构实体与油/发**重复计**了一遍。正确算法下容积只占 29% —— **容积不是约束**，
真正的约束是 12.4 的封装链。这条差点写进文档，留档以免重犯。

## 13 前提换成核动力 + 材料突破（2026-11-08）

### 13.2 最重要的发现：内嵌风扇在核动力下**数学无解**

这跟数值精度无关，是方程本身没有正解。

```
盘面积被机身深度卡死 → P ∝ T^1.5 ∝ m^1.5
动力系统质量 ∝ P ∝ m^1.5
⇒ 方程 m = A + B·m^1.5，B 过大时**无正解**
```

化学动力不会出这个问题，因为发动机质量是 MTOW 的**固定比例**，不随功率变，
反馈回路是断的。核动力的动力系统质量 ∝ 功率，回路闭合，于是发散。

实测：内嵌构型在 H = 4 / 6 / 8 / 10 / 12 m **全部无解**；
改用四具折叠吊臂（D = 0.6H，A ≈ 1.13H²，是内嵌的 7.3 倍）后全部有解。

> **结论：核动力机甲的风扇必须装到机身外面。**
> 这不是造型偏好，是「有没有解」的区别。

**为什么屏蔽是方向性的**：4π 全向屏蔽在 8 m 机体上要 20 t 级，直接压死。
阴影屏蔽只挡住「反应堆→驾驶舱」这条视线（1.8 m² 盘），0.11 t 就够。
代价是**背后与地面是热区**，作战时必须规定人员 100 m 外作业 —— 这条写进操作规程，不是回避。

### 13.4 基准构型 H=8 m 的质量闭合

| 项 | 质量 |
| --- | --- |
| 结构（+50y 材料，19.1 m³ 实体 × 450） | 19.10 t |
| 折叠吊臂结构 | 1.05 t |
| 堆芯 + 反射层（49.4 MWt ÷ 130 kW/kg） | 0.38 t |
| 闭式布雷顿机组（0.25 kg/kWe） | 5.74 t |
| 超导发电 + 电动机 | 1.84 t |
| 阴影屏蔽 | 0.11 t |
| 涵道风扇 + 风道（10 kg/kN × 444 kN） | 4.44 t |
| 散热器（64 m² × 2 kg/m²） | 0.13 t |
| **MTOW** | **34.9 t** |

链路：MTOW 34.9 t → 悬停推力 444 kN（T/W 1.30）→ 轴功率 22.3 MW
→ 堆热 49.4 MWt → **废热 27.9 MW** → 1400 K 散热器 **64 m²**。
可用散热面 163 m²（机翼 49 m² 双面 + 机体 55%），占用 39%，**够**。

### 13.5 新的短板是散热，而且越大越糟

散热面积 ∝ 废热 ∝ 轴功率 ∝ 重量 ∝ **H³**
可用表面积 ∝ **H²**
⇒ 比值 ∝ H，**越大越装不下散热器**。

H=4 时占 18%，H=8 占 39%，H=12 占 62%，H=16 占 87%，H=20 直接无解。

有意思的是屏蔽是**定值**（0.11 t），越大越摊薄 —— 这一项确实利好大机体，
但量级太小，被散热项完全盖过。所以尺度上限不是屏蔽决定的，
而是**机组质量的正反馈发散**：H ≈ 16 m 以上算不出解。

### 13.7 代价与作战约束（不回避）

1. **红外特征是致命的**：28 MW 定向辐射，5 km 外仍有 **89 mW/m²**。
   夜空里就是一支火炬。必须有「低功率热隐身模式」—— 把堆功率压到 20%、
   靠机体热容短时突防，代价是机动性归零。
2. **背后与地面是辐射热区**：阴影屏蔽的前提是机组在屏蔽锥内。
   地面人员、己方车辆不能站在堆尾方向 100 m 内。
3. **散热器是易损件**：64 m² 展开面，一旦被打穿热管就失去散热能力，
   所以必须有冗余回路 + 可抛弃设计。
4. **落地后不能马上检修**：堆停堆后余热仍需排出，需外接地面冷却。

### 13.8 这对建模意味着什么（覆盖 12.6）

| 项 | 化学方案（12.6） | 核方案（本节） |
| --- | --- | --- |
| 风扇 | 背部内嵌两个涵道 D=1.78 m | **四具折叠吊臂，D=4.8 m，展开跨约 12 m** |
| 背部 | 涡扇 + 散热格栅，厚 ≥1.2 m | 堆芯 + 布雷顿机组 + 阴影屏蔽盘，厚 ≥1.6 m |
| 机翼 | 剪式翼，S=56 m² | 剪式翼 **兼作散热面**，S=49 m²，上下表面铺热管 |
| 腿部 | 装油箱 | **不装油**，改为配重与作动着陆缓冲 |
| D/W | ≥0.47（风扇倒逼） | **≥0.47 仍成立**，但驱动它的从风扇变成动力舱 |
| 新增外形元素 | — | 吊臂铰链、散热翼展开机构、背部散热格栅、屏蔽锥 |

**原创性落点**（与 Unicorn / F-35B 都不同）：

1. **四臂吊扇 + 人形躯干**：Unicorn 无翼无扇，F-35B 是单风扇内置 —— 这个组合没有先例。
2. **散热翼 = 机翼**：把热管理做成气动面，是能量武器时代飞行器的典型解法，但用在人形机甲上没有现成参考。
3. **阴影屏蔽决定座舱位置**：机组必须坐在屏蔽锥里，这直接约束了头部与躯干相对堆芯的布局 —— 造型被辐射安全倒逼，这是很好的设定素材。
4. **无垂尾 + 差动矢量 + 吊臂差动**：四个吊臂的推力差可以直接产生偏航与滚转力矩，
   比气动舵面响应快一个量级，是悬停稳定的关键。

## 14 S2 局部灰模：头 + 胸 + 双肩 + 上臂 + 腰髋（2026-11-08）

S1 只回答了「线稿上有哪些板」，S2 要回答「按核动力那套约束把尺寸放开之后，
这些板堆起来还成不成立形」。所以 S2 的验收不是「像不像」，而是三条能算的：
分件数、闭合率、**尺寸链必须由真实零件长出来而不是拉伸包围盒凑出来**。

> **本节整体重写过四次。** 前三次都在「参数量级」里打转，全部被用户否掉
> （「怎么把高达的影子都改没了，别搞这么圆滚滚的」）。第四次才是对的：
> 问题不在参数，在**基元**（§14.5）。所以 §14.5 / §14.6 是本节的核心，
> 3 / 4 / 7 只是它的实测结果与翻车记录。

### 14.1 基准尺寸定案：H = 8.0 m（夹逼出来的，不是拍的）

§3 的扫描只回答「哪些机高有解」。有解 ≠ 该选。定 H 的是两头夹：

| 约束 | 判据来源 | 给出的界 |
| --- | --- | --- |
| 有效载荷下限 **1.96 t** | 30 mm 链炮 0.45 + 弹药 300 发 0.21 + 座舱/堆舱装甲 0.70 + 光电雷达数据链 0.35 + 乘员生保 0.25 | **H ≥ 8.0 m**（6% MTOW 的载荷位才装得下） |
| 散热占用比 ≤ 50% | §13.5 的 A_rad/A_avail | **H ≤ 8.0 m**（10 m 实测已到 50.0%） |
| 接地压力 ≤ 200 kPa | 软土通行上限，双足接地面积 `2×(0.11H)×(0.19H)` | H ≤ 11 m（未先到） |
| 机组质量正反馈 | `m = A + B·m^1.5` 无正解 | H ≤ 16 m（未先到） |

**四条界交集只有 H = 8.0 m 一个点。** 这台机甲的尺寸不是「我想要 8 米」，
是被载荷与散热同时卡住的唯一解。诚实标注：2.09 t 载荷位对 1.96 t 只有 6% 余量，
所以 S2 的载荷舱按 2.0 t 定死，不做扩容许诺。

### 14.2 动力舱容积账：质量算完还要算体积

质量闭合只看「多重」，不看「塞不塞得进」。12.5 t 动力系统需要的体积：

| 部件 | 质量 t | 假设密度 kg/m³ | 体积 m³ | 位置 |
| --- | --- | --- | --- | --- |
| 堆芯 + 反射层 | 0.38 | 2500 | 0.15 | 背包最深处（离座舱 1.42 m） |
| 闭式布雷顿机组 | 5.74 | 1200 | 4.78 | 背包中段 |
| 超导发电 + 电机 | 1.84 | 2000 | 0.92 | **四具吊臂内，直驱风扇** |

背包 2.30×1.38×2.32 = 7.36 m³ × 装机率 70% = **5.15 m³**；
胸部可用 3.09 m³ × 70% = 2.16 m³。机身内需求 4.93 m³ / 可用 7.32 m³ = **67%**。

> 硬表面重做后背包外形尺寸被肩甲/胸背板重新夹过一遍（§14.3），
> 容积从第一版的 7.57 掉到 7.36 m³，占用率 66%→67%。
> **余量只剩 6%，这条线到顶了** —— 再往包里塞东西只能改构型，不能改外形。

第一版我把布雷顿机组按 500 kg/m³ 估（当成空腔），得出需要 12.4 m³，
差点把方案判死 —— 实际 PCHE 印刷电路板式回热器的装机密度是 1200~1500 kg/m³。
**密度假设错了，结论就反了。**

> 真正逼电机上吊臂的不是容积（塞进机身也只到 78%，装得下但没检修通道），
> 是**铰链**：22 MW 机械功率过不了折叠关节。核电动力的天然解法就是电传。

### 14.3 尺寸链自洽性（实测包围盒 vs 目标）

> **本节是 S2 胸像期的数值，仅供追溯。** W/H 0.5600 在胸像期是「肩宽 / 上半身高 3.850」，
> 那不是 Unicorn 的口径 —— 正确口径是「肩宽 / 全高」。补腿到 7.920 后同一组零件
> 自动得到 W/H 0.5600。**现行值见 15.4，本节数字不要引用。**

| 量 | 目标 | 实测 | 偏差 |
| --- | --- | --- | --- |
| W/H | 0.561（Unicorn 实测） | **0.5600** | −0.2% |
| D/W | 0.627（同上） | **0.6244**（现 0.6250） | −0.4% |
| 包络 | — | **4.480 × 3.850 × 2.798 m**（现 7.920 高） | — |

这两个数不是模型缩放出来的：W 由肩甲外缘 ±2.240 定（肩甲宽 1.224、内缘 1.02），
D 由「座舱盖前凸 +0.772」与「折叠吊臂尾喷口 −2.025」两头定。**改任一零件都会把比例撞掉**，
这才是尺寸链自洽的意思 —— 比例是真实零件的副产品，不是先定比例再塞零件。

### 14.5 为什么第一版圆滚滚：基元选错，不是参数没调好

第一版所有主形体都用 `r3d.g_loft`。它的几何是**超椭圆放样**：14 个顶点沿截面均布，
相邻面夹角 360/14 ≈ **25.7°**。连续 25.7° 的小转角在视觉上就是曲面 ——
它的设计意图本来就是「方中带圆」。所以 expo 从 3.4 调到 4.2 再调到 6.0，
也只能在「圆」和「方中带圆」之间移动，**永远出不来锐棱**。

用户的原话是三句：「怎么把高达的影子都改没了」→「别搞这么圆滚滚的」→「第一性原理」。
把这三句翻译成几何约束就是 P1/P2/P3 三条（下表）。落地的第一件事不是改参数，
是**新开 `tools/hardsurface.py`**，把形状控制权从「基元参数」交回「调用方的多边形轮廓」。

新增三个基元（原先一个都没有，这就是根因）：

| 基元 | 用途 | 为什么必须新做 |
| --- | --- | --- |
| `loft_poly` | 沿 Y 逐层放样多边形 | `g_loft` 只能给超椭圆；折面必须由调用方给 4–8 边轮廓 |
| `ext_poly` | 多边形挤出 + 倒角 | 平面板件（胸甲、披膊、甲片）需要「一个平面 + 一圈斜切」 |
| `loft_z` | **沿 Z 逐层放样多边形** | 肩甲要「侧视轮廓 + 前后收刀口」。`loft_poly` 只能沿 Y 堆截面，做不出侧视姿态——这是第三轮才补的，补之前肩甲怎么调都是枕头 |

### 14.6 五条原则与第一性原理的对应

| 原则 | 内容 | 特斯拉式第一性原理的对应 | 落地处（可核对的具体数字） |
| --- | --- | --- | --- |
| **P1 折面** | 截面只准 4–8 边凸多边形，斜切量 ≥0.06×最小边；禁止连续小转角 | 「不做无法解释的曲面」——曲面必须有气动或结构理由 | 胸 4 层（最大宽在 y 5.58）、肩甲 7 边、髋 6 边、面罩斜板 |

| **P3 分缝** | 每条装甲缝落在内部结构边界上 | 「造型是结构的投影，不是贴上去的装饰」 | 胸竖缝→中脊侧壁（±0.30）、肩缝→吊臂铰座、腰缝→腰回转轴承、面罩缝→座舱盖框 |

P5 的执行手段是 `--views` 的**下排纯黑剪影**——那不是装饰图，是判据：
把剪影二值化之后，这四处凸起必须各自独立成块，不能互相粘成一片、不能被邻件吃掉。
这一条是从「加滤镜看效果」改成「去色看信息量」，也是唯一能客观验 P4 姿态的办法。

## 15 S3 全身落地：补腿、补前臂与手、倒角标定（2026-11-08 晚）

S2 停在髋（y 4.14），是一个**胸像**。这一节把它补成完整的 8 m 机体，
并给出一个容易被忽略的定量事实：**「不像高达」的主因是尺寸链没闭合，不是造型不对**。

### 15.1 决定性发现：W/H 0.561 是「肩宽 / 全高」，不是「肩宽 / 上半身高」

Unicorn 的 W/H = 0.561 指的是**肩宽比全高**。S2 只有上半身，
肩宽 4.48 m 配上半身高 3.85 m，实际 W/H = **1.16** —— 视觉上必然矮胖。

这意味着 S2 阶段所有「肩甲怎么调都不帅」的努力都打在了错误的靶子上：
**比例是错的，肩甲是无辜的**。补腿到 8.0 m 之后 W/H 自动回到 **0.5600**，
气质是尺寸链给的，不是造型给的。这一条值得写进流程：**先闭合尺寸链，再谈造型**。

腿长分配（髋底 4.14 往下）：

| 段 | y 范围 | 长度 | 说明 |
| --- | --- | --- | --- |
| 髋球 | 4.22–3.92 | 0.30 | 内构，露在裙甲下缘与大腿之间 → 负空间 |
| 大腿 | 4.00–2.44 | 1.56 | 宽 0.94（跨 x 0.26–1.20） |
| 膝 | 2.50–2.06 | 0.44 | 前凸 0.62（比大腿前缘 0.44 凸 0.18） |
| 小腿 | 2.14–0.86 | 1.28 | 小腿肚在 1.70（宽 0.96） |
| 踝 | 0.84–0.64 | 0.20 | 内构环，把小腿与脚断开 |
| 脚 | 0.72–0.00 | 0.72 | 长 1.24（z −0.58…+0.66），脚趾前伸 0.76 |

**脚前掌上限 0.76，卡在座舱盖前凸 0.772 之内** —— 再踩出去 D/W 就超 0.627。
这类「一个零件被另一头卡住」的连锁约束，才是尺寸链自洽的真实含义。

裙甲（厚重的主要来源，12 件）：前裙两片到 3.10、侧裙两片到 2.92（外缘 1.32）、
后裙两片到 3.00，每片上下两层叠压（山文甲）。三个作用都不是装饰：
遮髋关节、把下半身横向撑开、给大腿留摆动负空间。

### 15.2 倒角标定：3–9 cm 的倒角在 760 px 下只有 1–2 像素

补完腿之后全机仍然「像积木拼的」。查下来不是零件不够，是**倒角小于一个像素**：
各处 `c` 给 0.03–0.09，在 8 m 尺度上等于 3–9 cm；760 px 渲染、可见高度约 1.24×8 m
≈ 10 m，即 1 px ≈ 13 mm —— 一条 30 mm 的倒角只有 2.3 px，一条 90 mm 的 6.9 px，
在明暗量化后基本消失。

修法：`R()` / `B()` 里统一放大 **1.5 倍**，并夹在最小边的 28% 以内
（避免金线、线束、指块这类窄件被倒角吃掉整截面）。改完全机立刻「立」起来 ——
这是本轮性价比最高的一次改动，成本 10 行代码。

## 16 飞行控制构型决策：翅膀、鸭翼、额外推进器到底要不要

用户问的是一个工程问题而不是造型问题，所以答案也必须是一个可算的答案。
完整的计算脚本是 `tools/flight_control.py`，输入全部取自 `nuclear_mecha.py`
（H=8.0 m、MTOW 34.9 t、T/W 1.30、风扇 D=0.6H=4.8 m、吊臂 x ±1.52 / z −1.50 / y 5.92），
不另设参数。

### 16.1 判据先定，后算

| 角加速度 α | 判定 | 标定依据 |
| --- | --- | --- |
| ≥ 0.5 rad/s² | 可作主控 | 60°/s 姿态变化在 2 s 内完成，是人操机体的可接受响应 |
| 0.1–0.5 | 只能配平 / 精修 | 完成同样的动作要 4–20 s，跟不上飞行员输入 |
| < 0.1 | 无效，别装 | 完成要 20 s 以上，等于没有 |

**为什么用角加速度而不是力矩**：力矩绝对值没有意义，34.9 t 的机体和 3 t 的机体
同一个力矩差一个量级。判据必须归一化到「转动惯量」才有可比性。

### 16.2 转动惯量（估值，±30%）

```
roll  绕 Z（前后轴）   183,379 kg·m²     k·m(W²+H²)/12, k=0.75
pitch 绕 X（横轴）     156,701 kg·m²
yaw   绕 Y（竖轴）      60,880 kg·m²
```

用均匀长方体 ×0.75（质量向质心集中）估。**这是估值不是实测**，
真实资产要按分件质量分布积分。但三轴之间的**比例关系**是可靠的，
而决策只依赖比例 —— 这一点必须写清楚，否则数字会被误当成实测值引用。

### 16.3 四臂推力矢量：三轴能力完全不同，根因是一个结构事实

| 轴 | 力矩 N·m | α rad/s² | 到 60°/s | 判定 |
| --- | --- | --- | --- | --- |
| roll | 50,739 | 0.277 | 3.78 s | 仅配平 |
| pitch | 177,672 | **1.134** | 0.92 s | 主控 ✓ |
| yaw | 50,739 | **0.833** | 1.26 s | 主控 ✓ |

**关键结构事实：四具吊臂全在质心后方同一平面（z ≈ −1.50）。**

这决定了三轴力矩的来源根本不同：

- roll → 左右差动，有力臂（x ±1.52）→ 力矩 = 2·ΔT·x
- yaw → 左右差动，同样是 2·ΔT·x
- **pitch → 前后没有分布，差动恒等于 0** → 只能靠整机倾转 12°，
  让 760 kN 推力产生 93 kN 水平分量，再由「作用点高于质心 1.92 m」生成力矩

这不是设计缺陷，是所有四旋翼构型的共性。但它解释了一件事：
**pitch 是这台机器唯一「必须动整机才能控」的轴**，而 pitch 恰恰是飞行姿态里最要紧的。
§16.5 的 RCS 和 §16.4 的鸭翼，本质上都是在问「能不能给 pitch 补一条独立通道」。

### 16.4 鸭翼：不需要。低速无效，高速冗余

单侧 1.0 m²、CL 0.8、力臂 3.0 m（两侧合计 ×2）：

| 速度 m/s | q kPa | 力矩 N·m | α_pitch | 判定 |
| --- | --- | --- | --- | --- |
| 0 | 0.0 | 0 | 0.000 | 无效 ✗ |
| 50 | 1.5 | 7,350 | 0.047 | 无效 ✗ |
| 100 | 6.1 | 29,400 | 0.188 | 仅配平 |
| 150 | 13.8 | 66,150 | 0.422 | 仅配平 |
| 180 | 19.8 | 95,256 | **0.608** | 主控 ✓ |

**结论：不装。** 理由不是「不像飞机」，而是：

1. **悬停和低速时 q→0，鸭翼力矩为零** —— 而悬停恰恰是机甲最常用的工况；
2. 到 180 m/s 它才够主控，但那时推力矢量的 pitch 已经 α=1.134（§16.3），
   再叠一条 0.608 的通道**换不来新的控制能力**；
3. 唯一换来的是「关掉吊扇后还能控姿态」这一条冗余 ——
   这个冗余用 RCS 买更便宜（44 kg/具 vs 鸭翼 + 作动筒 + 结构加强）。

### 16.5 散热翼：这是唯一真正值钱的一条，但结论和直觉相反

散热面 64 m²（§13.5）。如果把它当升力面（CL 0.6）：

| 速度 m/s | q kPa | 升力 kN | 占重量 |
| --- | --- | --- | --- |
| 60 | 2.2 | 85 | 25% |
| 100 | 6.1 | 235 | 69% |
| 150 | 13.8 | 529 | 155% |
| 180 | 19.8 | 762 | **223%** |

看起来极美：180 m/s 时升力是重量的 2.2 倍，巡航时吊扇可以完全关掉，
省下 22.3 MW 轴功率 = 省掉约 80% 的废热。**但这个数被两个几何约束否掉了。**

16.5.1 第一个否掉它的约束：这 64 m² 不是一块翼面

64 m² 是**双面展开面**（散热器两面都散热），单面投影只有 32 m²。
更要紧的是：机身外表面积 ≈ 2(4.48×7.92) + 2(4.48×2.80) + 2(7.92×2.80) ≈ **140 m²**，
64 m² 的散热面相当于机身外表的 46% —— 它**本来就分布在机体蒙皮上**，
不是一个可以拿去当翼面的独立部件。要当翼面就得把它聚成一块，那是另一个结构。

16.5.2 第二个否掉它的约束：聚成一块之后装不下

要全托住 34.9 t（CL 0.6、180 m/s），需要投影面积 **S = 28.8 m²**。按展弦比展开：

| 展弦比 AR | 总翼展 m | 弦长 m | 相对机宽 4.48 | 可行性 |
| --- | --- | --- | --- | --- |
| 0.8 | 4.8 | 6.00 | 1.1× | 可接受 |
| 1.0 | 5.4 | 5.36 | 1.2× | 可接受 |
| 2.0 | 7.6 | 3.79 | 1.7× | 偏大（需折叠） |
| 4.0 | 10.7 | 2.68 | 2.4× | 不可接受 ✗ |
| 6.0 | 13.1 | 2.19 | 2.9× | 不可接受 ✗ |

两条硬约束卡死：

1. **弦长受背包深度限制（2.80 m）**：弦长卡 2.80 m 时要凑够 28.8 m²，
   翼展就得 10.3 m = 2.3× 机宽；
2. **低展弦比诱导阻力大，可用 CL 从 0.6 掉到 ~0.35** → 所需面积反涨到 49.3 m²
   → AR 1.0 时翼展 7.0 m。

**⇒ 翅膀做不成「巡航全托举」的主升力面，几何装不下。**
AR 4 以上的飞机翼（翼展 10.7 m 起）在一台肩宽 4.48 m 的机体上根本不可能常时展开。

16.5.3 装得下的最优解：16 m² 双侧短翼盒

| 方案 | 翼面积 m² | 翼展 m | CL 0.35 升力 kN | 占重量 |
| --- | --- | --- | --- | --- |
| 肩后短翼盒（双侧） | 8.0 | 4.0 | 56 | 16% |
| 肩后短翼盒（双侧） | 12.0 | 4.9 | 83 | 24% |
| **肩后短翼盒（双侧）** | **16.0** | **5.7** | **111** | **32%** |

16 m²、翼展 5.7 m（比肩宽 4.48 只宽 1.22 m）在 180 m/s 提供 **32% 重量**，
吊扇推力只需降到 68%。按动量理论（定盘面积下 P ∝ T^1.5）：

```
轴功率比 = (1 − 0.32)^1.5 = 0.555
省下 9.9 MW 轴功率（原 22.3 MW 的 44%）
= 省掉总废热 27.9 MW 的 36%
```

**注意这里没有用「功率线性下降」这个常见错误**。推力降 32% 不等于功率降 32%，
定盘面积不变时推力与功率是 1.5 次方关系，实际只降到 0.555。
这条折算如果不严格，结论会从「省 9.9 MW」虚报成「省 15 MW」。

### 16.6 额外推进器（RCS）：只做精修与失效备份

| 方案 | 单具 kN | 具数 | 力臂 m | 力矩 N·m | α | 判定 |
| --- | --- | --- | --- | --- | --- | --- |
| 冷气 RCS（1 kN 级） | 1 | 8 | 3.0 | 24,000 | 0.131 | 仅配平 |
| 热气 RCS（5 kN 级） | 5 | 8 | 3.0 | 120,000 | 0.654 | 主控 ✓ |
| 热气 RCS 大（20 kN） | 20 | 4 | 3.0 | 240,000 | 1.532 | 主控 ✓ |

8 具 1 kN 冷气 RCS 系统质量约 **440 kg = 1.3% MTOW**。

**结论：装冷气 RCS，不装热气 RCS。** 冷气 α 只有 0.131，做不了主控，
但它有两个不可替代的用途：

1. **悬停抑漂**：±0.1° 量级的姿态漂移，用吊臂差动去修会产生耦合振荡，
   用 RCS 是一阶直接作用；
2. **单具吊臂失效备份**：丢 25% 推力后，pitch 通道（本来就靠倾转）会瞬间失去基准，
   RCS 是唯一能在那 1–2 秒内保住姿态的东西。

热气 RCS 虽然 α 0.654 能主控，但 20 kN 级的推力器 + 推进剂储箱
在 34.9 t 上要占 3–5% 的质量，而它带来的是「替代一个已经能用的通道」——
不划算。

### 16.7 三条结论（回答用户的问题）

| 问题 | 答案 | 定量依据 |
| --- | --- | --- |
| 要不要鸭翼？ | **不要** | 悬停 q→0 力矩为 0；180 m/s 才 α 0.608，而推力矢量已 α 1.134 |
| 要不要翅膀？ | **要，但不是控制面** | 16 m² 双侧短翼盒：翼展 5.7 m 装得下，巡航提供 32% 升力，省 9.9 MW（44% 轴功率 / 36% 废热）。64 m² 全托举方案几何装不下 |
| 要不要额外推进器？ | **要，只装 1 kN 冷气 RCS 8 具** | 440 kg = 1.3% MTOW，α 0.131 仅配平；用途是悬停抑漂 + 单臂失效备份 |

一句话：**背包要加的不是「控制面」，是「翼盒」。** 控制能力四臂已经够了
（pitch/yaw 都是主控），缺的是散热和升力，而这两件事恰好可以用同一块面积做。

### 16.8 这条结论对几何的反作用（S5 的入口）

16.7 的结论直接解决了 15.5.3 的侧视问题 —— 不是靠「再调一次方块比例」，
而是靠**换一个部件类型**：

| 侧视问题 | 翼盒怎么解 |
| --- | --- |
| 躯干 0.157 的厚高比读作薄板 | 翼盒把前后厚度从 2.80 增到约 3.4（翼根前后各出 0.3） |
| 背包顶 7.30 冒过肩甲顶 7.16 | 翼盒顶压到 **6.95**（低于肩甲 0.21），层级恢复 |
| 背包只有一道直缝，无前后收束 | 翼根斜板 + 前缘后掠 22° → 侧视有「翼」的收束方向 |

体量核算：16 m² 双侧 = 每侧 8 m²。AR 1.0 时单侧翼展 4.0 m、弦长 2.0 m、
厚 0.22 m → 单侧翼盒体积 ≈ 4.0 × 2.0 × 0.22 × 0.6（梯形折算）≈ **1.06 m³**，
双侧 2.12 m³。背包现 7.36 m³，塞得下，占 29%。

**这条要留一个警示**：翼盒一旦加进背包，背包顶从 7.30 降到 6.95 之后，
原来的 7.36 m³ 硬容积会掉到约 6.4 m³ —— **容积和造型在这里是直接冲突的**，
必须先确认 7.36 m³ 里有多少是真必须的（堆芯屏蔽、冷却回路、吊臂铰座），
再决定能砍多少。这一条不做完，S5 的翼盒就只是把方块换成另一个方块。

> **§16.7 的 16 m² 后来没做成。** 实际落地是 5.17 m² —— 少掉的那 2/3 不是
> 设计偷懒，是**折叠**这个约束换来的：翼片必须在收纳态收进肩甲外缘之内，
> 而铰点就在 1.84，翼根弦宽（每侧 0.10 m）是硬吃掉的展向预算。
> 详见 §17。

## 17 折叠翼盒：SEED 自由 / 正义那条路走通了（2026-11-08 夜）

用户提的参考是 SEED 里自由、正义那种可折叠机翼，问「是不是可行路径」。
结论：**可行，而且比 §16 的固定翼方案更合适** —— 因为它的设定口径恰好和
§16 的计算结论对得上，落地后还顺手解决了 15.5.3 的侧视问题。

### 17.1 为什么自由/正义的机翼正好是这台机器该有的东西

自由高达的翼型推进器、正义的 Fatum-00，设定上都不是气动升力面，是
**推进器挂载 + 散热片 + AMBAC（姿态制御）效应面**。这三件事对应的正是
§16 算出来的三个结论：

| 设定功能 | §16 的计算结论 | 是否一致 |
| --- | --- | --- |
| 散热片 | 64 m² 散热面是本机第一短板（§13.5），且装不成主升力面 | ✔ 一致 |
| 推进器挂载 | 翼尖力臂 3.56 m 是四臂 1.52 m 的 2.34× | ✔ 一致 |
| AMBAC 效应面 | 大气层内赚不到控制权（α 0.078），真空/稀薄大气才成立 | ✔ 一致（限定工况） |

所以这条路不是「抄造型」，是**同一个物理问题在设定侧的正确答案**。
反过来说：如果当初坚持做飞机翼（AR 4 以上），翼展 10.7 m 起，一方面装不下，
另一方面也违背了它自己的设定。

### 17.2 挂点：为什么必须挂 1.84，不能挂背包侧壁 1.20

背包侧壁 y 5.62–7.24 那一段，被**折叠吊臂收拢段**（x 1.20–1.78）整条占住了。
翼盒只能挂在 1.84，也就是**叠在吊臂外面一层**。这不是妥协，是自由/正义的
本来挂法：机翼是独立一层，叠在背包之外，不是从背包里长出来的。

铰点定在 **(1.84, 6.60)**，低于肩甲底 6.52 一点 —— 这样三片叶的根部
全部藏在肩甲后面（肩甲 z −0.54…0.50，翼盒 z −1.80…−1.44，两者 z 不重叠，
是前后关系不是穿插关系），正视图里翼从肩甲后上方「长出来」而不是「贴在腋下」。

### 17.3 三片不等长扇展开：三次翻车

| # | 症状 | 真实原因 | 修法 |
| --- | --- | --- | --- |
| 1 | 渲染出来是**三根细刺**，不是翼 | 叶片放在 X-Y 平面、弦长沿 Z → **板面法线朝 Y**，正面只看到 0.11 m 厚度 | 板面法线必须朝 **Z**（前后）。这是「翼」和「鳍」「刀」的分界 |
| 2 | 三片糊成**一整块楔形**，看不出层叠 | 三片**等长**，无论扇角多大并集都是一个楔 | 改**不等长** 1.45/1.80/2.15，三个翼尖连成上升阶梯 —— 那才是「羽」的读法 |
| 3 | 整组读作**两臂上举**，不像翼 | 扇角只到 26° 且取在肩高，接近水平 | 铰点下移到 6.60、扇角拉到 12°/24°/37°，立成 V 字 |

**第 4 次翻车是单位错，必须单独记**：`Node.rot` 的单位是**度，不是弧度**
（`r3d.Rx/Ry/Rz` 内部自己转弧度）。第一版套了 `math.radians(-87)`，
−87 被当成 −87 度 ≈ 0 度，三片叶全躺在水平位不动，**包围盒一点没变**。
我换了三版造型才发现是单位错 —— 症状是「改了参数模型不动」，不是「形状不好看」。

### 17.4 两个构型，两套规格（不能混着报）

| 构型 | 全机包络 W × H × D | 相对本体 | 说明 |
| --- | --- | --- | --- |
| 本体（不含翼盒） | **4.480 × 7.920 × 2.800** | — | **W/H 0.5600、D/W 0.6250，与线稿 0.561 对口径** |
| 收纳（翼折 88°/84°/80°） | 4.676 × 7.920 × 2.800 | 每侧 +0.10 m | 只多出翼根弦宽 |
| 展开（仰角 12°/24°/37°，后掠 16°） | 7.117 × 7.974 × 3.008 | 每侧 +1.32 m | 翼展 **7.12 m = 1.59× 本体宽** |

**为什么要把本体单独量**：折叠翼在几何上等于**把展向长度换成弦向宽度**，
翼根必然外凸 —— 这是折叠的代价，不是没折好。拿含翼包络去比 0.561，
只会得到「比例崩了」的假结论。所以 `stats()` 现在报两套数，
翼盒挂在独立父节点 `wings` 下，单独 collect 一次即可。

这也顺带修掉了一个更早的隐患：**翼展是另一条规格**，和全高并列，
不能塞进 W/H 一个数里。

### 17.5 定量账（`python3 tools/wing_box.py`，参数直读模型）

```
叶片 3 片，长 1.45 / 1.80 / 2.15 m，半弦 0.46→0.10，厚 0.075
叶面积   单侧 2.59 m²   双侧 5.17 m²
翼盒质量 ~57 kg（11 kg/m² 钛蜂窝+铰+作动筒）= 0.2% MTOW
```

| 项 | 数 | 依据 |
| --- | --- | --- |
| 散热面外置 | **10.35 m²**（5.17 投影 × 两面）= 64 m² 的 16% | 双面散热 |
| 巡航升力（CL 0.45 / 180 m/s） | 46.2 kN = 重量 **13.5%** | q = 19.8 kPa |
| 吊扇推力可降到 | **86.5%** | 1 − 0.135 |
| 轴功率比 | **0.805**（动量理论 `P ∝ T^1.5`） | (0.865)^1.5 |
| 省轴功率 | **4.4 MW** = 22.3 MW 的 20% | — |

**CL 取 0.45 而不是低展弦比的 0.35，理由是缝翼效应**：三片叠展形成隔离流，
等效多段翼，比单块同面积板 CL 高。这是「三片」相对「一整块」唯一在气动上的
好处，也是选扇形的第二个理由（第一个是折叠）。

翼尖游标（§16.6 的 RCS）单侧力臂 3.56 m，但：

| 方案 | 力矩 N·m | α_roll | 判定 |
| --- | --- | --- | --- |
| 冷气 1 kN × 4（翼尖） | 14,235 | 0.078 | 无效 |
| 冷气 1 kN × 8（四臂 + 翼尖） | 28,470 | 0.155 | 仅配平 |
| 热气 5 kN × 4（翼尖） | 71,175 | 0.388 | 仅配平 |
| 四臂差动（对照） | 50,739 | 0.277 | 仅配平 |

**⇒ 翼尖游标补不上 roll。** 1 kN 级 4 具只有 α 0.078，比四臂差动还弱；
要主控得 5 kN 级热气系统，那是 20 kN 总推力、3–5% MTOW 的代价。
所以它的定位仍然是悬停抑漂 + 单臂失效备份，**不是**新增一条主控通道。
**翅膀在控制上的价值只在 AMBAC（真空/稀薄大气）成立，大气层内它就是散热+升力件。**

### 17.6 顺手把背包顶压低了 0.18

15.5.3 记的「背包顶 7.30 冒过肩甲顶 7.16」本轮一并修掉：舱体顶 7.18→7.06、
顶盖 7.26→7.12、上甲板 7.12→7.00、布雷顿顶段 7.04→6.92。
现在背包顶 7.12 **低于肩甲顶 7.16**，侧视的层级恢复了。

代价是硬容积：舱体高度少 0.12 m，约 **−0.4 m³**（7.36 → 约 6.96 m³）。

### 17.7 仍未解决

## 18 头部：不是一只巨大的全景眼（2026-11-08 夜）

> 用户问：「头部从实用角度考虑的话，是不是应该是一个巨大的全景摄像头比较好，
> 感觉好像没啥其他作用，高达的原始设定里头部是干啥的」

### 18.1 先回答设定侧：RX-78-2 的头部装了什么

| 部件 | 设定功能 | 依据 |
| --- | --- | --- |
| 头顶主监视器 | 主光学系统，负责瞄准与变焦 | 百度百科「头顶部的主监视器」；MAHQ 将头部列为 sensors 总成 |
| 后脑监视器 | 后方视野 | 百度百科「后脑部的后监视器」 |
| 双眼 | **副**光学传感器 / 辅助射击摄像机 | 百度百科「人眼部位的双监视器（传感器）」；NamuWiki 将联邦机概括为「主摄（头顶）+ 双眼副摄」 |
| 额头 V 字天线 | **不定向**（全向）天线，通讯 | 百度百科「额头配备的 V 字型不定向天线」 |
| 头部 60 mm 巴尔干炮 ×2 | CIWS：拦截导弹/小型机、警告射击、打轻装甲 | MAHQ「2 × 60 mm vulcan gun, mounted in head」；Gundam Wiki：弹药少，连射不到 1 分钟 |
| 传感器作用距离 | 5,700 m | MAHQ 机体参数 |

**★ 一处必须标清楚的读法差异**：民间长期有「主光学传感器其实是额头那块四方格，双眼只是副摄」
的说法（Wikiwand 中文条目即持此说），与百度百科「头顶部主监视器」不完全一致。
两者的共同点是：**主摄只有一个，双眼是副的**。这一点不影响后面的结论。

### 18.2 设定里早就有「360°」这一层，但它被明确限定为只做显示

一年战争之后，联邦机普遍采用**全周监控系统**：把辅助光学传感器铺满机体，
把 360° 影像送进驾驶舱。但设定同时写了它的边界 ——

> 这些辅助光学传感器**只用于显示周边景象**，瞄准与变焦仍由头部的**主摄像机**
> 与武器上的辅助瞄准传感器承担。（NamuWiki「mono eye」条，联邦机段落）

也就是说，**「全向」与「高分辨可指向」在设定里是两件东西，分装在两处**。
用户设想的「一个巨大的全景摄像头」等于把这两件事塞进同一颗镜头里，
而设定早在 Z 高达时代就把它们拆开了。

### 18.3 吉翁单眼是这条结论的反证，不是例外

单眼（mono-eye）的设定恰好是「**一个镜头 + 让它动**」，而不是「一个镜头 + 铺满全向」：

- 单眼装在头内**水平轨道**上左右滑移，靠**移动产生视差基线**，因此能对数十公里外的
  目标测距；垂直视野靠颈关节点头，没有颈关节的重装甲机另加**纵向轨道**。
- 单眼内置激光测距/LiDAR，但**主动测量会被敌方察觉**（这是它主动测距的代价）。
- 因为只有一只眼，吉翁机**必须给每把枪都装辅助瞄准传感器**，
  靠「头部 + 武器」两点做三角测量 —— 相当于现代坦克车长周视镜与炮长镜分离。

**⇒ 结论：一个镜头要能测距，前提是它能移动（或用第二个点做三角）。
固定不动的全向镜头，在测距上是死路。** 这条直接否掉了「巨大全景摄」的核心诉求。

### 18.4 三笔账

**① 像素与带宽**（全球面 4π sr，像素数 = 4π / IFOV²，12 bit、60 fps）

| 全向瞬时视场 | 像素 | 未压缩带宽 | 20:1 压缩后 |
| --- | --- | --- | --- |
| 10.3′（3 mrad） | 1.4 Mpx | 1.0 Gb/s | 0.05 Gb/s |
| 3.44′（1 mrad） | 12.6 Mpx | 5.8 Gb/s | 0.29 Gb/s |
| 1.72′（0.5 mrad） | 50 Mpx | 36.0 Gb/s | 1.80 Gb/s |
| 1.03′（0.3 mrad） | 140 Mpx | 100.8 Gb/s | 5.04 Gb/s |
| 0.34′（0.1 mrad） | 1,257 Mpx | 905 Gb/s | 45.3 Gb/s |

**对照**：8 Mpx 装在 15°×10° 的窄视场上 → IFOV **0.075 mrad = 0.26′**，
分辨率比 140 Mpx 的全向还高 **4 倍**，像素少 **17 倍**，带宽少 **17 倍**。
全向铺满的每一 mrad 都在为「此刻不看的方向」付费。

**② 深度**（双目测距 ΔR = R²·θ_d / b，取视差分辨率 θ_d = 0.3 mrad）

| 基线 | 25 m | 50 m | 100 m | 200 m | 400 m |
| --- | --- | --- | --- | --- | --- |
| 0.26 m（现眼缝） | 0.7 m | 2.9 m | 11.5 m | 46 m | 185 m |
| 0.65 m（头宽内可行） | 0.3 m | 1.2 m | 4.6 m | 18.5 m | 74 m |
| 1.20 m（肩部宽基线） | 0.2 m | 0.6 m | 2.5 m | 10 m | 40 m |

**单孔径全景没有深度**。而双目在 100 m 外就已经烂掉（±4.6 m），
所以远端深度只能靠 LiDAR / 雷达 / 结构光 —— 那是**另一套传感器**，不是「更大的镜头」。
顺带一条比例事实：8 m 机体 / 1.75 m 人 = 4.57×，人的 65 mm 瞳距等效应为 **0.297 m**，
现眼缝基线 0.26 m 大致就是「人体等比」，不是随意取的。

**③ 单点失效与热**：头部是首要被弹面（设定里头被打掉是常态），一个大窗口 = 一次命中就全盲；
分布式小窗口有冗余。且核动力机体的头部在整机最高点，最适合当散热/排气口，
大面积光学玻璃反而挡了散热路径。

### 18.5 头部真正的四条作用（一条要打折）

| # | 作用 | 量化 | 强度 |

### 18.7 明确不建议：头部火神炮

**结论：不装，也不留炮口造型。**

## 19 翼盒结构校核：不是板撑不住，是铰撑不住（2026-11-08 深夜）

> 用户：「现在这小翅膀，你觉得这个结构能撑得住吗，你这个算的也太抽象了」

**这句批评成立。** §16/§17 给的全是系统级的数（面积、升力、功率、像素），
没有一处是「这块板受多少力、应力多少、会不会鼓」。补齐在 `tools/wing_struct.py`。

### 19.1 先量：这是一根 0.92 m 弦、75 mm 厚的悬臂板

梁高只有 75 mm —— 这是它所有问题的根源：**翼片的「梁」就是板厚本身。**

### 19.2 三条载荷

| 工况 | 依据 | 最外片受力 |
| --- | --- | --- |
| A 巡航升力 | 46.2 kN 按面积分到 6 片 | 9.45 kN |
| B 阵风/侧滑 | q(180)=19.8 kPa · S 1.058 m² · Cn 1.0 | **21.0 kN** |
| C 鸟撞 | 1.8 kg @180 m/s，10 ms 停住 | **32.4 kN** |

最外片只有几 kg，阵风载荷 21 kN ≈ **285 g**。不是算错，是「大展长 + 轻板 + 高速」的必然。

### 19.3 弯曲应力：1.2 mm 空壳在鸟撞下不过

许用 333 MPa（7075-T6，FS 1.5）。

| 面板厚 | 截面模量 ×1e-6 m³ | A 升力 | B 阵风 | C 鸟撞 | 判定 |
| --- | --- | --- | --- | --- | --- |
| 1.2 mm | 82.8 | 107.9 | 239.7 | **369.8** | **不过** |
| 1.6 mm | 110.4 | 80.9 | 179.8 | 277.3 | 过 |
| 2.0 mm | 138.0 | 64.7 | 143.8 | 221.9 | 过（余量 33%） |
| 2.5 mm | 172.5 | 51.8 | 115.1 | 177.5 | 过 |

### 19.4 面板屈曲：肋救不回来，只能上夹芯

σ_cr = 4π²E/[12(1−ν²)]·(t/b)²，t=2.0 mm，工作压应力 143.8 MPa：

| 未加筋面板宽 b | 0.92 | 0.60 | 0.40 | 0.30 | 0.22 | 0.15 |
| --- | --- | --- | --- | --- | --- | --- |
| σ_cr MPa | 1.22 | 2.87 | 6.46 | 11.49 | 21.36 | 45.94 |
| 占工作应力 | 0.8% | 2.0% | 4.5% | 8.0% | 14.8% | 31.9% |

**肋距压到 0.15 m 也只有 32%** —— 薄面板靠加肋救不回来。必须夹芯：
面板 + 铝蜂窝（E_c 1.0 GPa、G_c 0.4 GPa）后控制项变成**面板皱曲**
σ_wr ≈ 0.5·(E_f·E_c·G_c)^(1/3) ≈ **1,518 MPa**，不控制。

### 19.5 铰点：阵风下要吃 41 kN·m

| 项 | 值 |
| --- | --- |
| 三片根弯矩合计（升力） | 18.40 kN·m |
| 三片根弯矩合计（**阵风**） | **40.90 kN·m** |
| 铰销 Ø30 双耳受剪 τ | 44.6 MPa（许用 200）→ 销本身没问题 |

纯销铰**抗不了弯矩**，展开态必须靠撑杆或限位块：

| 撑杆力臂 | 0.30 m | 0.50 m | 0.70 m | 1.00 m |
| --- | --- | --- | --- | --- |
| 轴力 | 136.3 kN | 81.8 kN | **58.4 kN** | 40.9 kN |

**三片共用一个铰座（力臂 0.3 m）要 136 kN，做不出来** —— 必须每片独立双耳铰。

### 19.6 质量与包络

面板 2.0 mm + 蜂窝芯：双侧 6 片 86.2 kg，+ 铰座/撑杆 18 kg = **104 kg = 0.30% MTOW**。
展开态限速 274 m/s（许用弯矩 46.0 kN·m），**仍覆盖 180 m/s 巡航** ——
所以「高速收纳」不是强度逼的，是阻力与铰点寿命逼的。

### 19.7 结论

1. **材料强度**：1.2 mm 空壳鸟撞不过；2.0 mm 面板 + 夹芯三工况全过（最大 222 MPa）。
2. **屈曲**：空壳加肋无效，必须夹芯（皱曲 1,518 MPa 不控制）。
3. **机构**：阵风 41 kN·m，撑杆 58 kN 级，**每片独立双耳铰 + 展开限位块**。
4. **一句话：不是板撑不住，是铰撑不住。** 板换夹芯就够，铰必须重做。

*★ 同时修正上一轮口头的「翼盒 57 kg」：那是按 8–10 kg/m² 面密度拍的。
按 1.2 mm 蒙皮 + 翼梁复算是 49 kg，按 2.0 mm 夹芯是 104 kg。
差值来自壁厚假设 —— **没标注假设的数就是错数**，这里补上。*

## 22 部件复杂度：加了件数不等于加了细节（2026-11-08 深夜）

### 22.1 判读尺：为什么 73 件看着还是简单

| 量 | 数值 | 说明 |
| --- | --- | --- |
| 部件图每格 | 560 × 900 px | 三列三行 |

| 上一版百叶 | 8 mm = **1.3 px** | 等于不存在 |

| 分件缝 | 22 mm | `seam` | 把大面切块，缝里露暗色 |

## 24 作画方式解析与比例改造：腿加长、躯干收、前臂收、细节重排（2026-11-08 深夜）

用户四条直觉：**腿加长 / 小腿大腿稍细 / 躯干变小 / 小臂变细**，再加一条 **增加细节**。
这一节先把 Unicorn 与 Freedom 的作画方式拆开，再把四条直觉逐条量化，最后落地。

### 24.1 Unicorn 与 Freedom 不是一种画法

两者常被并称「SEED/UC 高复杂度」，但驱动机制完全不同 —— 混着抄必然两头不靠。

| 维度 | Unicorn（角木肇 / Katoki） | Freedom（大河原原案 + 重田智作画） |
| --- | --- | --- |
| 复杂度的**发动机** | **分件缝**：缝是功能性变形缝（NT-D 时装甲滑开露红框体） | **大面轮廓**：先定剪影，再在必要处加一条主折线 |
| 缝的密度 | 高，缝窄，走直线、沿体轴 | 低，缝少而长，只落在结构边界 |
| 刻线/装饰线 | 几乎没有 —— 靠件与件的**位移**出层次 | 依附于折线，不做满铺 |
| 形体拆分 | 外壳必须能分成「可滑动的块」，块与块之间是导轨 | 外壳是一块整甲 + 一条折线，折线两侧明暗不同 |
| 色块的作用 | 白甲 / 红框是**两套几何**，展开才露出 | 白蓝红黄**承担了分件的读法** |
| 灰模状态下的可读性 | 好（缝与台阶都是几何） | **差** —— 去掉配色后 Freedom 反而比 Unicorn 难读 |
| 比例 | 腿长、脚大、肩宽/全高 0.56、头小 | 腿同样长，但躯干更厚（要装 MMI 与翼） |

**这条差别决定我们的做法**：我们的目标是灰模可读（没有配色可依赖），
所以必须走 **Unicorn 的缝驱动路线**，而不是 Freedom 的色块路线。
§22 里「复杂度 = 台阶数 × 台阶尺寸」其实就是这条路线的量化表达。

### 24.2 两者真正共同的六条（这才是该抄的）

1. **腿长 53–56% 全高**（胯点算起，不是从裆部算）；
2. **脚大**：脚长 0.09–0.11 H，脚宽 ≈ 单腿宽 ×1.15，且有明确的踝收；
3. **腰窄胸宽**：腰宽 / 胸宽 ≈ 0.72–0.78，沙漏靠腰的收口读出来；
4. **前臂 ≥ 上臂，但绝不 1.6 倍以上**（人形实测 1.1–1.3）；
5. **头小**：SEED 实机约 8.2 头身（口径是「头顶到下颌底」）；
6. **细节密度沿体轴不均匀**：躯干与头密，四肢疏 —— 均匀满铺会把机体读成「一片麻点」。

第 6 条本轮**没有做到**（本轮是均匀加），见 24.9。

### 24.4 量测方法必须改：点带法量不出收放

第一版量腿径用「±0.10 m 点带取 max」，量出 `0.136 m`、`0.0 m` 这类荒谬值。两个原因：

1. **薄切片切空**：腿是按 y 层放样的，层与层之间只有侧壁。切片落在两层之间就什么都切不到；
2. **带宽抹平收放**：层距最大 0.417 m（拉伸后），带宽必须 ≥ 半层 + 0.02 = 0.22 m。
   量 1.66 处的小腿肚时会把 1.16 处的胫中一起圈进去，取 max → **局部收放全部消失**。

改用 **三角形-平面真求交**（`tools/prop_measure.py::slice_at`）：对每个三角，
若 y 落在它的 [ymin, ymax] 内，求三边与平面的交点，收集所有交点取 x/z 范围。
不受层距影响，0.10 m 步长能分辨每一处收放。

### 24.6 三个位移常数不能共用（一个只有包络查不出的 bug）

比例层 `xform()` 用嵌套节点实现「绕 pivot 的仿射重映射」：

```
外层 pos = (px, dy+pivot, pz)   scl = (sxz, sy, sxz)
内层 pos = (−px, −pivot, −pz)
→ x' = px + sxz·(x − px)
```

**踩的坑**：外层 `pos` 的 x 槽第一版写的是 `0`。当 `sxz = 1.0`（腿不需要横向缩放）时，
`0 + 1.0·(x − 0.78)` 等于把整条腿**平移到中线** —— 两条腿重合成一条、手臂缩进躯干。
出图就是「只有一条腿的机体」。

★ **致命之处是包络完全查不出来**：畸变是对称的，`本体 W/H` 仍然 0.5600、
`D/W` 仍然 0.61、零件数不变。**只有看图才能发现**。这条必须写进流程：
比例改动不能以包络为验收，必须出图。

## 26. 主干剥离：剥掉全部外挂之后，剩下的东西更难看（2026-11-09）

### 26.1 结论先行

问题原话是「把外部的那些枝枝叶叶都去掉，只保留机体的主干，这个你可以做到吗」。**能。**

做法不是删代码，是加一个 `--clean` 全局开关（`s2_graybox.py` 的 `CLEAN`），
同一套参数、同一套材质、同一台相机，切一下就得到两种构型。这样「剥离」这件事
可以随时**再上回去**，而不是一次性把旧版本毁掉。

| 指标 | A 现构型 | B 主干构型 | Δ |
|---|---|---|---|
| 零件数 | 649 | **248** | −61.8% |
| 三角形 | 19,728 | **7,036** | −64.3% |
| 宽 W | 4.480 m | 4.480 m | **0** |
| 高 H | 7.930 m | 7.930 m | **0** |
| 纵深 D | 2.809 m | **2.515 m** | −10.5% |
| D/W | 0.6270 | **0.5614** | −0.0656 |
| 可见投影线长 | 389.8 m | 336.7 m | −13.6% |
| **V%（竖线占比）** | 36.1% | **45.2%** | **+9.1 pt** |
| S%（设计斜线） | 11.3% | 11.1% | −0.2 pt |

这张表本身就是结论，三个数必须连起来读：

1. **零件砍掉六成，轮廓只缩了一成。** W 和 H 一点没变、D 只少 0.294 m。
   说明外挂件在**剪影**上从来不是主体 —— 它们占的是**密度**，不是体量。
   这也解释了为什么「去掉大冰箱」这个动作在图上远不如想象中明显：
   **纵深的大头是脊柱本身，不是动力舱。**
2. **剥完之后「呆板」更明显：V% 从 36.1 升到 45.2。** 外挂件里有大量斜线
   （折翼后缘、吊臂、浮游炮的收口），它们一直在替躯干和四肢**稀释**竖线密度。
   剥掉它们，剩下的就是腿、臂、胸、脊柱四组直筒。**外挂件不只是在遮丑，
   它们本身也是全机斜线的供应方。**
3. **D/W 从 0.6270 掉到 0.5614。** 这条是口径后果，见 26.6 —— 0.627 这个锚点
   本来就是靠背包撑出来的，要走 Unicorn 路线必须重推，不能拿它继续当验收线。

### 26.2 什么算「枝枝叶叶」：四类，逐条给理由

判据只有一条：**把它单独拿掉，机体是否仍然成立（能承力、能自圆其说、
不留下无法解释的洞）。** 按这条判，只有四类：

| # | 件 | 位置 | 为什么算枝叶 |
|---|---|---|---|
| ① | 左右动力舱 + 折叠吊臂 + 翼盒 | 脊柱两侧 | 外挂在脊柱上，剥掉后脊柱自己承力、机体成立。**这才是「大冰箱」的本体** |
| ② | 三具浮游炮（+ 三联炮架） | 背包顶 | 独立武器，正视图里读作两块打孔的板；剥掉后背包顶仍是完整甲面 |
| ③ | 折叠翼三片 | 身侧收纳态 | 收纳态 35° 垂在身侧，正视图读作「挂了两把刀」；剥掉后肩甲的挂点才露出来 |
| ④ | 肩后吊臂铰座 / 警示段 / 铰接环 | 肩甲后缘 | 唯一功能是挂 ①③，剥掉后只剩四个无解释的凸台 |

**不删的只有一件：脊柱。** 见 26.3。

顺带纠正一个误判：**头部那两根 V 鳍不是枝叶。** 它在 `head` 节点内，
是 MS 的绝对辨识点之一（§18 已定头是唯一辨识点，V 鳍是头的一部分）。
本轮判图时它看起来像「两根刀插在肩后」，但那是**装配错误**，不是分类错误 —— 见 26.4。

### 26.3 脊柱为什么不能删

两条独立的理由，任意一条就够：

1. **结构**：它是胸（y ≥ 5.16）与髋（y ≤ 5.18）之间**唯一的承力件**。
   删掉之后后背是一个贯穿的洞，胸和髋只剩前面那层甲皮相连 —— 那是壳，不是机体。
2. **容积**：§23 的容积账里 1、2 号布雷顿机**住在动力舱里**（各 1.593 m³）。
   剥掉动力舱后只剩脊柱的 2.305 m³ 毛容积 / 1.614 m³ 可用，
   **够 1 台（1.593）不够 3 台**。所以 `--clean` 明确是**造型研究体，不是可飞构型**，
   标题里也照这么写。这一点不能含糊过去，否则又变成一次「看起来达标」。

### 26.4 剥掉外挂会留下洞：两处，一处必须补、一处是装配错

这是本节最值得记的一条。**外挂件一直在替躯干遮丑**，剥掉它们，躯干自己的
缺陷才暴露。两处，性质完全不同：

**(a) 胸的背面（已补，上一轮做过）**
胸背面 z = −0.749、x ±1.13、y 5.26–7.04，背视里是一整片死黑的大平面
（光从正面来，背面全在阴影里）。补法是**中脊 + 左右两片背甲 + 横向压条**三层，
不是一整片 2.1 宽的板（那是 §25.3 那块「灰门」的重演）。
几何（4 层，上窄下宽、上薄下厚）：

```
(y, 半宽x, z0, z1) = (5.06, 0.34, −1.50, −0.56) / (5.40, 0.42, −1.68, −0.56)
                     (6.60, 0.40, −1.62, −0.58) / (7.06, 0.26, −1.24, −0.62)
纵深 1.34 → 最深 1.12；上端只到 1.24（不给「背鳍比肩高」的错误剪影）
```

**(b) 腋下那道缝（本轮才查出来）**
射线检测沿前向打 `(x = 1.15, y = 5.50)`：

| 构型 | 命中面数 | 读法 |
|---|---|---|
| A 现构型 | 3 | 挡住 —— **但挡住它的是折翼（z −1.86…−1.38）** |
| B 主干构型 | **0** | 直接穿到背景 |

也就是说：胸主板最宽只到 ±0.96（y 5.70–6.30），插座只到 ±1.04（y ≥ 6.16），
上臂内缘在 ±1.24 → **y 5.2–6.1 之间是一条 0.20 m 宽、0.9 m 高的通缝**。
这条缝从建模第一天就在，一直被折翼盖着，所以从来没人发现。

补法（`build_chest` 4b 腋下封板）：外缘 1.00 → 1.14 → 1.22 逐层外张，
前缘只到 z 0.20（胸主板 0.62，**退在后面，不跟胸抢主面**），
上端 6.40 收回 1.20 与插座咬住。**不做「一整块侧板」**，理由同 26.4(a)。

**(c) V 鳍不是洞，是把根种错了位置**
`ant` 的根边原来在 `y ≈ 7.06`（**下颌高度**），而头壳在那一层只有 ±0.26，
根却从 x 0.28 起 —— 于是整条叶身从根到尖**全长在头壳外面**：
y 7.5 处内缘已到 0.67、头只到 0.36，**中间 0.31 m 是背景灰**。
正视图读作「两根刀插在肩后」，和折翼收纳态「挂了两把刀」是同一个错误。

改法：根边抬到眉檐线（7.54–7.62），内缘起点压回 x 0.08（进头体），
叶身从额头斜出去 —— 内缘在 y 7.74（头顶）之前始终 ≤ 头壳半宽，之后头顶已经
没有了，**结构上不存在可见的背景缝**。

代价必须说清：**外张角被逼到 54°（Unicorn 约 28°）**。头顶只到 7.74、总高上限 8.0，
竖直预算只有 0.42 m；想保持 28° 就得把叶身拉到 1.2 m 长、尖端顶到 8.6 ——
那是触角不是 V 天线。**这是预算约束，不是造型偏好。**

### 26.6 口径后果：0.627 这个锚点是靠背包撑出来的

§25 花了整章把 D/W 从 0.6138 推到 0.6270（D 2.809）。剥掉外挂之后：

### 27.3 纵深到底该分给谁：这是「冰箱感」的真正根因

### 28.2 裆线重测：为什么旧数是错的，新数也不是「腿长」

三个版本、三次错法，按顺序记下来：

| 版本 | 做法 | 读出的数 | 错在哪 |
|---|---|---|---|
| v1（§27.4） | 取「腿件 bbox 的顶」当髋线 | U 0.641 / O 0.531 | 腿件 bbox 顶含**髋关节球、大腿甲、侧裙**，根本不是裆 |
| v2 | 顶点扫中线，`min|x|/H < 0.02` 判填满 | U 0.535 / O **0.865** | 我们的腿缝绝对值只有 0.04 m = 0.005H，阈值 0.02 直接判成「填满」，量到了胸口 |
| v3（本版） | **渲染前视遮罩，逐行看中线 3 列是否全实** | U **0.541** / O **0.444** | 无（v3 与 v2 对 Unicorn 的结论一致 0.535 / 0.541，互为交叉验证） |

v3 的实现要点（`tools/legline_ruler.py`）：

- 掩码必须用 `RR.render()` 的**第一个返回值**（覆盖率），不能用「像素亮度 < 128」判——
  机体亮面 199、背景 140，两者都 > 128，那样判出来的「实体」只剩描边黑线，
  裆线被读成 0.839H（那是画框里的一条腿）。
- `meta['cy']` 必须给 **H/2**。给 0 会让相机盯着脚底，画框只框进下半身。
- 自下而上找第一行「连续 3 行全实」，像素→高度用「最低实体行 = 0H、最高实体行 = 1H」标定。

**关键发现：这个「裆线」测量的是「中线第一次被遮住」的高度，挡住它的是前裙下沿。**

实测我们自己的分层：

| 件 | y 范围 | ÷H |
|---|---|---|
| skirt（裙） | 3.441–4.781 | 0.434–0.603 |
| hip（髋节点） | 4.321–4.761 | 0.545–0.600 |
| leg_L（腿件） | 0.000–4.401 | 0.000–0.555 |

→ 量到的 0.444H 就是**裙底**，比髋节点还低 0.101H。
参考模型的裙下沿在 0.484H 且中缝开着，所以它的中线到 0.541H 才被遮住。

**所以「腿看起来短」这件事，修法是抬前裙下沿到 ~0.50H + 中缝开 V 口，
一毫米骨头都不用动。** 加长大小腿要动整条腿装配链、改重心与步态，
而观众看见的只是裙摆那 0.10H —— 代价和收益完全不对称。

> 附带撤销一个命名：`legline_ruler` 里那个「腿最细处」**不能叫膝线**。
> 参考模型实测 0.485H，而人形膝盖在 0.26–0.30H。名字叫错，读数就会被拿去当膝盖用。

### 28.3 肩甲：为什么是「整体缩放」而不是「再改一次轮廓」

前六次改的都是 `SH_PROF` 的顶点。到第六版轮廓已经对了：
平顶 / 外缘垂直 / 只在外上角挑一个尖 / 上下两片叠压 / 披膊三层 / 前缘下唇。
**但整块甲在三个方向上同时超尺寸**。同尺实测（H 归一到 10）：

| | x 范围 | y 范围 | z 范围 | 宽 × 高 × 深 |
|---|---|---|---|---|
| Unicorn `shoulder_armor_assy_G` | 0.971–2.156 | 7.509–8.866 | ±0.44 | 1.185 × 1.357 × 1.110 |
| Ours（改前） | 1.286–2.825 | 7.540–9.380 | ±0.71 | 1.539 × 1.841 × 1.425 |

**偏大 28–36%，三轴同步。** 轮廓怎么调都只是「一块大的对形状甲」。

★ 为什么会偏大：肩甲外缘 2.240 当初是**给折叠翼根留的遮盖**
（`build_shoulder` 第 6–8 件：铰座 x 1.12–1.36、折叠吊臂 x 1.20–1.78，
翼根要压在肩甲外缘之内）。`--clean` 剥掉翼之后，这块宽度**没有任何受力理由**，
是纯粹的遗留物。**这和 §26.4 的「腋下洞」「前脸铁皮」是同一个病：
外挂件一直在替躯干遮丑，剥掉之后才看得见它留下的尺寸。**

**改法：三轴独立映射，固定点反解。**

```
x' = ax + kx(x − ax)     ax = −0.067   kx = 0.770
y' = ay + ky(y − ay)     ay =  5.842   ky = 0.747
z' = kz · z                            kz = 0.780
```

| 轴 | 原 → 目标 | k | 不动点 |
|---|---|---|---|
| x | 1.02 → 0.770（内缘往里走）<br>2.24 → 1.710（外缘） | 0.770 | −0.067 |
| y | 6.00 → 5.96（下沿略降）<br>7.44 → 7.036（顶） | 0.747 | 5.842 |
| z | ±0.565 → ±0.44 | 0.780 | 0 |

改后实测：`sh_L` x 0.770–1.709、y 5.970–7.061、z ±0.44
→ **0.939 × 1.091 × 0.881 m**，三轴同时落在参考值的 1% 内。

`xform()` 只有一个 `sxz`，把 x 和 z 绑死，写不出这个映射，
所以新增 `squeeze3(name, child, anchor, k)`：三轴各给各的比例与不动点。

#### 两个代入错误（都值得记住）

**① anchor 是「不动点」，不是「要固定的那条边」。**
第一版把 anchor 写成内缘 1.02，于是映射变成 `x' = 1.02 + 0.77(x − 1.02)`，
外缘只从 2.240 收到 1.935 —— **渲染图和改之前一模一样，差点被当成「改了没用」**。
不动点必须从「原坐标 → 目标坐标」反解：`a₀ = a / (1 − k)`。
判据：改完必须**先量 bbox 再渲图**，bbox 没动就是参数没生效。

**② 等比缩放（第一版 0.75 三轴同缩）会把手甲变成「一片挑出去的薄鳍」。**
等比缩同时把下沿从 6.52 抬到 6.39、把内缘留在 1.02 ——
于是它**既不盖上臂**（臂顶 6.48，重叠只剩 9 cm），**也不接躯干**（胸侧 1.17）。
正视图上就是「肩上挑出去一片小三角」。
→ **肩甲不是「按自己的比例缩」，是「按参考机体的位置摆」**：
内缘要往里压进胸侧之内才接得住，下沿要压过上臂顶才盖得住。
等比缩只保证形状对，不保证能装上去。

## 29 纵深：不是「太厚」，是「厚错了地方」

### 29.1 结论先行

1. **撤掉「脊柱 0.95 m 太厚、要砍到 0.5」这条 P0。** 那个 0.95 是 `waist` 件的

### 30.4 从这张表读出的四条规则（这才是「为什么」）

**① 角度必须正负交替。** 上表前脸的符号是 `−+−+−+−+−`，没有连续三段同号。
壳体是**叠瓦**的：上一片的出口角必须比下一片的入口角更「收」，两片之间才有一条搭接缝。
单调同号的轮廓 = 一块铸造件，这正是我们「板甲太光滑」的病根。

**② 悬臂段的根部必须有料。** 裙甲挂在腰封 4.56 上，是悬臂：
根部弯矩最大 → 根部最厚（0.40 m），尖端弯矩趋零 → 尖端最薄（0.12 m）。
参考前裙 45° 的斜切 = 等强度梁的斜边。我们原来那一版根部与腰封之间空 0.25 m，
既没有料也没有斜切，所以侧视读作「插在腰上的一片薄鳍」。

**③ 近水平段（|角| > 60°）全部是关节。** +85.8°（膝）、−72°（腰）、−66°（裙下沿）
这些段长度只有 0.10–0.30 H，位置全在可动处。**水平段 = 分件线**，不是造型。
反过来：要和参考一样「有机械感」，就要在关节处**主动**做这种 60° 以上的短段。

**④ 长段给形，短段给机构。** len ≥ 0.5 的段角度都在 8–25°（造型皮），
len < 0.3 且角度 > 40° 的是机构/搭接。长度和角度是**反相关**的——
一条 0.4 H 长、45° 的段是不存在的（那是一块斜坡，不是甲）。

### 30.6 还没对上的（按缺口排）

| 缺口 | 量 | 语法上的说法 |

| 脚 0–10% | −0.87 H | 参考脚背是 −55.4° 的长斜面（0.79 H），我们是 90° 的竖墙 |
